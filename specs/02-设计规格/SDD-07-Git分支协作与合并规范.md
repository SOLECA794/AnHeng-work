# SDD-07 · Git 分支协作与合并规范

> 状态：v1.0（2026-10-15）
> 提出方：A 组（组长）
> 用途：消除「直接推 main」「分支堆积无人合并」「共享文件反复解冲突」三类问题，明确分支命名、开发流程、合并责任和冲突收口规则。
> 适用范围：全组所有代码仓库提交。

## 1. 分支策略

### 1.1 分支模型

仓库只保留一条长期分支：`main`。不设 `develop`、`release/*` 等中间分支。

| 分支类型 | 命名格式 | 生命周期 | 用途 |
| --- | --- | --- | --- |
| 长期分支 | `main` | 永久 | 可部署基线，保持单测全绿 |
| 功能分支 | `feature/<组>-<任务号>-<简述>` | 任务完成即删 | 单人或单组开发 |
| 规格分支 | `spec/<规格名>` | 评审合入即删 | 规格文档变更 |

示例：`feature/c-t12-asset-service`、`feature/d-t22-verification`、`spec/sdd-02-malicious-script`。

### 1.2 硬规则

1. **禁止直接向 `main` 提交开发代码**。所有功能开发在 feature 分支上进行，通过合并进入 main。
2. **合并必须经过 PR 或组长确认**。本地合并完成后推 main 前，至少在群里发一句「已合并 XX 分支，单测 N 条通过」，等组长确认再 push。
3. **feature 分支合入 main 后立即删除**（远程和本地都删），不保留历史分支。
4. **main 必须保持单测全绿**。任何合并后单测变红，合并人负责立即修复或回滚。

## 2. 开发流程

### 2.1 个人开发循环

```
main ──► feature/xxx ──► 自测通过 ──► 提合并请求 ──► 组长确认 ──► 合入 main ──► 删分支
```

1. 开工前：`git checkout main && git pull`
2. 建分支：`git checkout -b feature/<组>-<任务号>-<简述>`
3. 开发：小步提交，commit message 写清楚做了什么
4. 自测：跑 `python -m unittest discover -s tests/unit -t tests/unit`
5. 完成后：推分支到远程，在群里通知组长
6. 组长合并后：删本地和远程分支

### 2.2 多人协作顺序

当多个分支待合并时，按以下顺序：
1. **规格分支先合**（spec/*）——消除「代码用了规格未定义值」的不一致
2. **被依赖的分支先合**（如 B 的注册表加固 → C 的适配器 → D 的结果处理）
3. **文档/配置类分支最后合**（README、待办清单等人人都改的文件，集中收口）

## 3. 冲突处理

### 3.1 高频冲突文件

以下文件多人都会改，是冲突高发区：

| 文件 | 冲突原因 | 收口规则 |
| --- | --- | --- |
| `requirements.txt` | 各人各自加依赖 | 取并集，按「运行依赖 / 测试依赖」分组注释 |
| `src/core/errors.py` | 各组新增错误码 | 错误码全局唯一，新增前查 SDD-03 已定义表 |
| `src/tools/contract.py` | 契约模型变更 | 以最新合入的契约版本为准，后合分支适配 |
| `tests/README.md` | 各组追加测试说明 | 取并集，按 T 任务号分节 |
| `docs/01-项目治理/03-待办事项清单.md` | 各组更新任务状态 | 取并集，版本号递增 |

### 3.2 冲突解决原则

- **业务逻辑冲突**：后合的分支适配先合的接口，不要保留两套实现。
- **错误码/枚举冲突**：以 SDD 规格定义为准，不以某个人的代码为准。
- **文档冲突**：一律取并集，不丢任何一方的内容。
- 解冲突后必须重跑全量单测，不能只跑自己写的那部分。

## 4. 合并验证清单

每次合入 main 前，合并人必须确认：

- [ ] `python -m unittest discover -s tests/unit -t tests/unit` 全部通过
- [ ] 无残留冲突标记（`<<<<<<<` / `=======` / `>>>>>>>`）
- [ ] 新依赖已写入 `requirements.txt`
- [ ] 待办清单状态已更新
- [ ] 合并 commit message 写清楚合了哪条分支、怎么解的冲突

## 5. 分支清理

- 每周五组长检查一次远程分支列表，已合并的立即删除。
- 本地定期执行 `git remote prune origin` 清理已删除分支的远程跟踪引用。
- 不保留「备用分支」「存档分支」——代码在 git 历史里，不需要靠分支名留存。
