# SDD-10 · 复测闭环（T25）

> v1.0 实现提案，随 PR 评审；2026-10-17，D。依据 SRS-02 F5.4、SDD-02 finding.status、SDD-03 §4.5。
> 本功能依赖 T24 的事务告警能力，PR 以 T24 功能分支为基线，按 T24→T25 顺序评审合并。

## 1. 状态语义

复测须重新执行原规则针对当前目标的检测。确定仍命中为 MATCH→CONFIRMED；完整成功且原规则无命中为 CLEAN→FIXED；已经 FIXED/RETESTED 后再次 CLEAN→RETESTED（本契约明确为“再次复测通过”）。未修复的风险保留 CONFIRMED，不能以 RETESTED 掩盖；FALSE_POSITIVE 不执行修复复测。

超时、无绑定、规则变化、抓取不完整/非成功响应、目标/权限不匹配、来源过旧或无覆盖证明均为不确定，保留原状态。页面后来无命中不等于之前是误报。

## 2. 执行与事务

两阶段：先在短事务内鉴权、锁资产/风险、记录 RUNNING 和请求 UUID；事务外调用可信 runner；再锁定并比较业务快照，检查观测时间和授权，提交状态、结果历史及 T24 告警周期。

业务快照包含风险身份、状态、来源元数据、资产范围及同风险的最新业务时间。排除仅供告警使用的元数据和本次 reservation；检测期间业务变化返回 40902，不覆盖新状态。CLEAN/MATCH 必须有来源与规则 SHA256、完整覆盖证明，观测时间须晚于已有业务时间，且在请求开始与完成之间。

`raw_data.retest_pending` 仅保存当前请求的 UUID、处理人、开始时间及快照摘要；更新时保留原业务时间。AgentLog 的 `finding.retest:{findingId}:{UUID}` 作为持久化执行历史与幂等记录，必须保留。相同 UUID 的终态请求不重复执行；执行中请求拒绝重入。五分钟未完成的 reservation 可由新请求过期收回，旧执行结果不能覆盖新请求。多资产批量不是整体事务，每条风险独立提交。

状态、终态记录、清除 reservation 与告警联动同事务；审计/告警写入失败全部回滚，保留可追踪的 RUNNING，后续可过期回收。不宣称崩溃后一定执行“恰好一次”。

## 3. 可执行 runner

提供真实 T20 敏感信息离线 runner：服务端绑定原目标、规则 ID、规则快照与风险身份；使用受信任取样器取得当前 ScanDocument，检查现行资产范围、HTTP 成功、覆盖完整与精确目标，重新运行原规则。绑定/取样器不从客户端提交；不从 T21 脱敏 URL 猜原始路径。其它检测器通过同一结果契约接入，没有适配器时明确不确定，不假装已执行。

本地验收取样器只读固定合成样例，不扫描外部站点。生产取样器仍须落实超时、重定向范围、完整响应及非破坏限制。

## 4. 接口与历史

路由工厂默认不挂载，必须注入真实鉴权。SEC_OPS 可 POST `/api/findings/{id}/retest`；只接受可选 requestId（UUID），禁止客户端给出 verdict/URL/角色。SEC_OPS/RULE_ADMIN 可 GET `/api/findings/{id}/retests?limit=...` 查询执行历史，仍限制启用且显式授权的资产。

服务提供按资产有界批量复测（最多 20 条，afterId 分页）；批次 UUID 派生单项 UUID，重试已执行单项可回放。每次选择当前最新风险记录，不是冻结的全站作业快照。结果只含编号、枚举、时间、摘要和告警回执，不含原内容、URL、规则正文或异常详情。历史 status 表示当次结果，currentStatus 明确表示当前状态，避免将旧的修复记录误认为当前仍安全。按资产扩展接口 POST `/api/auth-scopes/{id}/retest`，接受 requestId、limit、afterId。

## 5. 验收边界

验证真实离线规则执行、修复/未修复/再次复测/复现、幂等、并发请求、过期回收、旧快照/跨资产/禁用资产/规则漂移拒绝、事务回滚、告警周期与脱敏历史。隔离 SQLite 不等于 PostgreSQL 联调；不包含真实 JWT、前端、平台和其它扫描器在线复测。
