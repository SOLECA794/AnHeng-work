# SDD-01 · 系统架构与关键技术设计

- 规格状态：基线 v1.0
- 需求依据：SRS-01、SRS-02（功能条目 F1–F7）

## 1. 总体架构

```
┌─ 智能体运行层（恒脑安全智能体平台）──────────────────────────┐
│  任务规划 → 工具选择 → 编排执行 → 结果关联分析 → 报告生成        │
│  对话交互（自然语言发起巡检/查询/报告）                        │
└────────────────────────┬─────────────────────────────────┘
                         │ OpenAPI（智能体调用能力服务）
┌────────────────────────▼─────────────────────────────────┐
│ 能力服务层（自研，Docker 部署）                               │
│  API 网关：鉴权（JWT）、限流、统一响应 {code,message,data}      │
│  services/：资产、页面发现、调度、检测任务、结果、告警、报告、基线 │
│  tools/：开源工具统一适配器 + 自研检测器（篡改/外链挂马/敏感信息）│
│  agent/：恒脑编排适配（任务规划与工具调用轨迹落库）              │
└────────────────────────┬─────────────────────────────────┘
                         │ 命令/API（限速、超时、非破坏白名单）
┌────────────────────────▼─────────────────────────────────┐
│ 工具执行环境                                            │
│  开源工具：Nuclei（漏洞模板）、OWASP ZAP（被动扫描）、          │
│            Wappalyzer（指纹）；爬虫（页面发现）               │
│  自研检测器：篡改基线对比、恶意外链/挂马特征、敏感信息规则扫描     │
└────────────────────────┬─────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│ 数据层：PostgreSQL（资产/页面/任务/风险/告警/报告/审计）          │
│  Redis（任务队列、限流计数、缓存，可选）                       │
└─────────────────────────────────────────────────────────┘

┌─ 管理端（Web）──────────────────────────────────────────┐
│ 资产与规则配置 / 巡检可视化 / 告警复测 / 报告导出 / 审计       │
└─────────────────────────────────────────────────────────┘
```

分层职责：
- 智能体运行层（恒脑）：承担任务规划、工具选择、结果关联分析的"智能"部分；通过 OpenAPI 调用能力服务；
- 能力服务层：承担全部业务规则（资产、调度、检测流水线、结果处理、告警、报告），是核心业务所在；
- 工具执行环境：隔离开源工具与自研检测器，统一适配、限速、非破坏约束；
- 数据层：业务与结果数据自持；
- 管理端：配置与可视化入口，与智能体对话并行可用。

## 5. 关键设计

### 5.1 检测流水线（核心闭环）

```
触发（人工/定时/智能体请求）
  → 页面发现（范围校验 → 爬取 → 去重 → 入库）
  → 指纹识别（Wappalyzer → 组件/版本）
  → 并行检测
       ├─ 漏洞与弱配置（Nuclei / ZAP 被动）
       ├─ 外链挂马（自研检测器）
       ├─ 篡改对比（基线哈希 vs 当前）
       └─ 敏感信息（规则扫描）
  → 结果归一化（统一 Finding 结构）
  → 去重与关联（dedup_key）
  → 验证（二次确认/人工确认）
  → 分级（CRITICAL…INFO）
  → 告警 / 报告
  → 复测（修复后再检）
```

流水线设计要点：
- 阶段状态可观察（任务状态机：QUEUED → DISCOVERING → SCANNING → ANALYZING → DONE / FAILED）；
- 单阶段失败不阻塞整体（失败降级 + 重试上限）；
- 所有结果幂等落库（dedup_key 唯一约束）。

### 5.2 智能体编排（恒脑集成，基于开放接口文档）

恒脑对接收敛在编排适配层 `agent/`，对外提供统一 `AgentProvider` 接口，恒脑为当前实现、可替换（工业级：平台绑定最小化）。

```
AgentProvider
  ├─ execute(sid, agentId, inputs, stream)      # 同步/流式执行（恒脑 execute）
  ├─ stop(sid)                                  # 停止（恒脑 execute/stop）
  ├─ asyncSubmit(agentId, inputs) → taskId      # 异步任务提交（task/submit）
  ├─ asyncStatus(taskId) → status               # 1运行/2完成/3取消/4失败（task/status）
  ├─ asyncMessages(taskId, full) → messages     # 结果消息（task/messages）
  ├─ resume(messageId, inputs)                  # 交互回答（execute/resume）
  └─ upload(file) / download(fileId)            # 文件（file/upload、file/download）
```

调用模式（按场景选择）：

| 模式 | 场景 | 说明 |
| --- | --- | --- |
| execute 流式（SSE） | 智能体对话、即时交互 | `mode=preview` 消息按 `message_id` 聚合；`from` 标识思考/执行/结果；`ext: reason=1` 分离推理过程 |
| execute 非流式 | 简单调用 | 返回 `session/results/token_usage` |
| 异步任务（submit → status → messages） | **巡检长任务** | 不阻塞对话；结果全量/增量拉取 |
| 交互回答（resume） | 人工确认环节（授权确认、范围确认） | 流式输出中出现 `mode=question` 时渲染问题，回答后 resume 恢复执行 |

关键实现点：

- 鉴权：`appKey + sign`（HmacSHA256，见恒脑接入说明 §2）；凭据仅存能力服务（环境变量），前端不可见，签名服务端生成；
- 智能体侧编排：在恒脑能力中台可视化编排巡检智能体（入口 → 插件工具/知识库节点 → 结果汇总），输入参数（target_url/scope/check_types/sensitive_rules）与输出参数与能力服务 API 对齐；可参考 AgentManifest；
- 状态码映射：恒脑业务状态码（-402/-403/-301/-304/-500 等）映射为本项目错误码（SDD-03 §3，编排层不可用 → 50001）；
- 审计：每次恒脑调用写 agent_log（接口、参数摘要、状态、耗时、token 用量）；
- 降级：恒脑不可用时，智能体对话报 50001；巡检调度可绕过对话直接走能力服务流水线（业务闭环不依赖恒脑在线）。

### 5.3 工具层设计

统一接口：

```
ToolAdapter
  ├─ id / name / description        # 工具注册信息（供智能体选择）
  ├─ capability()                   # 能力声明：检测类型、适用对象
  ├─ run(target, params)            # 执行（统一超时、限速、错误处理）
  ├─ non_destructive_check()        # 非破坏校验（强制）
  └─ normalize(raw_output)          # 输出归一化 → Finding 标准结构
```

- 开源工具以容器或独立进程运行，能力服务通过命令/API 调用，全部走限速与超时；
- **工具白名单机制**：工具注册表（`tool_registry`）为唯一事实源——每个工具必须登记（name/能力声明/非破坏声明/限速参数/启停状态）方可被执行；执行前强制校验注册表 + `non_destructive_check()`；未登记、停用或破坏性工具一律拒绝并留痕（详见 `docs/02-质量与验收/03-工具清单与合规声明.md`）；
- 破坏性动作（利用、注入、爆破）禁止；
- 新增工具 = 新增适配器 + 注册（评审） + 非破坏校验，不改核心。

### 5.4 资产与页面发现

- 授权校验：每次发现与检测前校验 URL 归属（域名白名单 + 路径前缀）；
- 爬取约束：范围、深度、限速、robots（可配置）、超时；
- 页面去重：URL 规范化（去参数序/片段）+ 内容哈希；
- 基线：首次巡检或手工设置生成页面内容基线，用于篡改对比。

### 5.5 结果归一化与去重

Finding 标准结构：

```
{ type, severity, title, url, evidence, impact, suggestion,
  tool_name, raw(JSON), dedup_key, first_seen, last_seen, status }
```

去重键生成：`md5(规范化URL + finding_type + 证据特征)`；
归并策略：同键保留最早记录，更新 last_seen 与出现次数；跨工具同风险由智能体关联分析合并展示。

### 5.6 分级模型

- 基础分级规则：漏洞按 CVSS 映射；挂马/篡改/敏感信息按命中规则与影响面定级；
- 影响面因子：页面重要性（首页/登录页/核心路径）、暴露范围；
- 智能体在规则基础上生成影响说明与修复建议（模型生成 + 规则兜底）。

### 5.7 调度与定时巡检

- 巡检计划（schedule）→ 调度器按时触发 → 生成检测任务（task）→ 走流水线；
- 支持手动触发与立即执行；任务失败可重试（配置上限）；
- 告警去重：同 dedup_key 的新增风险仅首次告警，修复后复现再告警。

### 5.8 非破坏性与合规实现

| 控制点 | 实现 |
| --- | --- |
| 授权边界 | 资产白名单校验（发现/检测入口强制）；未授权直接拒绝并留痕 |
| 限速 | 全局 + 按站点 QPS 限制；工具并发上限 |
| 最小权限 | 服务账号最小权限；工具容器非 root；敏感样例字段脱敏展示 |
| 审计 | agent_log / operation_log 全量记录；管理员可查 |
| 非破坏 | 工具白名单（注册表强制校验）+ 适配器强制 non_destructive_check；禁用利用类参数 |
| 工具白名单 | 工具注册表（唯一登记/能力声明/非破坏声明/限速/启停）；未登记或停用工具不可执行；执行前强制校验并留痕 |

### 5.9 恒脑运行与平台无关

- 智能体逻辑部署在恒脑（任务规划、工具编排、对话）；能力服务通过 OpenAPI 暴露；
- 工具、数据自持（PostgreSQL），不依赖平台存储；
- 编排适配层隔离：统一 `AgentProvider` 接口，恒脑为当前实现；恒脑 API 变更只改 `agent/` 适配层；
- 凭据安全：恒脑 appKey/appSecret 仅存能力服务环境变量，前端与外部系统不可见。

### 5.10 工业级与可扩展原则（本项目全局约束）

所有技术选型与设计遵循以下原则（不把本项目当 demo 对待）：

1. **通用性**：技术栈选用生态成熟、社区广泛使用的技术（Python/FastAPI、React/TypeScript、PostgreSQL、Docker），避免小众或平台私有方案；
2. **可扩展性**：新工具、新检测类型、新报告模板的扩展不动核心——工具经注册表接入，检测器实现统一接口，报告走模板化；
3. **可替换性（脱离平台绑定）**：恒脑通过 `AgentProvider` 适配层隔离，模型/编排可替换；数据与工具自持，不依赖平台存储；
4. **可维护性**：分层清晰、统一响应与错误码、审计全量、规格文档与实现一致、数据库脚本版本化；
5. **工程化**：Docker Compose 部署、配置外置、日志/指标可观测、测试与测试集版本化、CI 可落地（Git 规范见治理文档）。

## 6. 部署架构

```
Docker Compose
├── server            # 能力服务（FastAPI，/api）
├── web               # 管理端（静态托管，可选独立容器）
├── postgres          # 业务数据库
├── redis             # 缓存/队列（可选）
└── tools             # 工具执行环境容器（nuclei/zap/爬虫，按需）

恒脑平台：SaaS/私有化（OpenAPI 接入，配置外置）
```

部署要点：
- 配置外置（环境变量）：数据库连接、JWT 密钥、恒脑 API 地址与 Key、限速参数、工具容器地址；
- 生产启用 HTTPS；管理端与能力服务同域或 CORS 白名单；
- 数据库脚本纳入版本管理（db/schema.sql、db/data.sql），可重复执行。

## 7. 关键风险与对策

| 风险 | 对策 |
| --- | --- |
| 恒脑平台版本演进/正式接口与现有开放文档差异 | 编排适配层隔离（AgentProvider）；以平台最新接口文档为准；Phase 0 实测清单见恒脑接入说明 §8；预留降级（调度直接走能力服务流水线） |
| 检测误报影响指标 | 验证环节（二次确认 + 人工确认）+ 误报标记；测试集评估校准规则 |
| 工具执行不稳定/超时 | 统一超时、失败降级、重试上限；工具容器隔离 |
| 授权边界被绕过 | 入口强制白名单校验 + 全链路留痕；复测/报告均带归属校验 |
| 敏感数据在展示/报告中泄露 | 样例脱敏、证据裁剪、报告权限控制 |
| 规模化巡检性能 | 页面发现异步队列化；检测并行化；限速与并发可控 |
