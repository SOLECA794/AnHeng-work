# SRS-01 · 项目概述与需求基线

- 规格状态：基线 v1.0
- 对应赛题：面向网站安全风险评估与敏感信息防泄露的智能巡检智能体（安恒，企业赛题）

## 1. 课题信息

| 项 | 内容 |
| --- | --- |
| 赛题名称 | 面向网站安全风险评估与敏感信息防泄露的智能巡检智能体 |
| 命题企业 | 杭州安恒信息技术股份有限公司 |
| 交付形态 | 可在恒脑安全智能体平台中运行的智能体原型；管理端；开源安全工具编排层；完整工程文档与测试报告 |
| 关键约束 | 授权前提下运行；编排**合规开源工具**；**避免破坏性测试**；结果可解释、可跟踪、可复测 |

## 2. 项目背景

政企网站长期暴露在互联网中，安全风险主要来自四类：

1. **组件漏洞与弱配置**：站点使用开源组件/框架存在已知漏洞（CVE）、常见弱配置（默认口令、错误响应头、目录列举等）；
2. **内容安全**：页面被篡改、被挂马（植入恶意脚本/跳转）、存在恶意外链；
3. **敏感信息泄露**：运维人员误发布文件、代码或业务数据，导致源码、配置文件、密钥、个人信息等暴露；
4. **巡检能力不足**：传统人工巡检覆盖有限、响应滞后、结果不可追溯、无法周期性复测。

本赛题拟以"智能体 + 工具编排 + 风险闭环"的方式解决上述问题：智能体在恒脑平台上完成任务规划与工具编排，周期性对授权站点执行风险评估、内容完整性检测与敏感信息检查，并把结果沉淀为可解释、可跟踪、可复测的风险闭环。

## 3. 项目核心目标

1. 实现**授权资产配置**：支持录入授权域名、巡检范围、巡检周期和本单位敏感信息定义（关键词、正则、文件类型或样例）；
2. 实现**资产与页面发现**：自动发现站点及下属页面/资源，按策略控制发现范围与深度；
3. 实现**多类风险检测**：按策略调用并编排合规开源工具，识别常见漏洞、弱配置、恶意外链/挂马、页面篡改及敏感信息暴露；
4. 实现**风险闭环**：结果去重、验证、分级，给出证据、影响、修复建议；支持定时巡检、基线对比、告警、复测和报告导出；
5. 实现**智能体能力**：任务规划、工具选择与编排、结果关联分析、证据解释与修复建议，运行于恒脑安全智能体平台；
6. 满足**安全合规**：授权边界、限速、最小权限、日志审计、非破坏性。

## 4. 用户角色与权限

| 角色 | 使用端 | 核心操作 | 数据范围 |
| --- | --- | --- | --- |
| 安全运维人员 | 管理端 + 智能体对话 | 授权资产配置、巡检计划管理、查看风险结果与报告、确认/复测 | 本人负责的站点数据 |
| 内容/规则管理员 | 管理端 | 敏感信息规则维护、工具配置、告警规则维护 | 全局规则配置 |
| 系统管理员 | 管理端 | 用户管理、审计日志、系统配置、工具启停 | 全系统数据 |

权限实现要求：接口按角色鉴权（401 未登录 / 403 越权）；授权资产仅对授权用户可见；审计日志仅管理员可查。

## 6. 非功能需求

### 6.1 检测效果（对应评价指标：检测效果 30%）

- 在统一测试集上评估漏洞 / 挂马 / 篡改 / 泄露四类的召回率、准确率、误报率；
- 测试集可复现（搭建可控靶场与样例集），评估结果记录进测试报告。

### 6.2 安全合规（对应评价指标：安全合规 10%）

| 项 | 要求 |
| --- | --- |
| 授权边界 | 所有巡检仅针对已授权域名；未授权域名一律拒绝；页面发现与检测均校验归属 |
| 限速 | 请求频率受限（单位时间请求上限可配置），避免影响目标站点 |
| 最小权限 | 工具以最低权限运行；服务账号权限最小化；敏感数据（凭据/样例）脱敏展示 |
| 日志审计 | 每次巡检、工具调用、结果操作留痕，可追溯 |
| 非破坏性 | 仅使用被动/非破坏检测，不进行漏洞利用、注入、爆破等破坏性动作 |

### 6.3 工程化与创新（对应评价指标：工程化与创新 15%）

- 部署易用：Docker Compose 一键编排；配置外置（环境变量）；
- 稳定性：工具超时/异常降级、调度任务可重试、结果幂等落库；
- 扩展性：工具通过统一适配器扩展，新增工具不改核心；
- 可视化：管理端呈现资产、任务、风险分布、趋势；报告可视化导出；
- 创新价值：智能体任务规划与结果关联分析的智能化程度。

### 6.4 性能

- 单站点常规巡检在可接受时间内完成；千级页面规模可巡检；
- 管理端列表查询、报告生成响应流畅。

### 6.5 可维护性

- 统一响应结构、错误码；审计日志可查；数据库脚本纳入版本管理；规格文档与实现一致。

## 7. 范围边界

- **不做**未授权扫描 / 渗透测试 / 漏洞利用（含验证性利用），全部检测非破坏；
- **不做**目标系统修复动作（只给修复建议，不自动改目标配置）；
- **不做**绕过 WAF/认证的检测；对需要登录态的页面仅做可达性与公开内容检测（可配置跳过）；
- **不做**移动端 App；管理端为 Web；
- 敏感信息检测以本单位定义的关键词/正则/文件类型/样例为准，不预设"通用全量敏感库"（可内置公共规则作为可选）。

## 8. 术语表

| 术语 | 含义 |
| --- | --- |
| 授权资产 | 已获授权并录入系统的站点/域名及巡检范围 |
| 页面发现 | 对授权站点进行页面与资源爬取、登记与去重 |
| 检测任务 | 一次对某站点/页面的检测执行（含类型、状态、起止时间） |
| Finding | 检测发现的风险条目（含类型、级别、证据、影响、修复建议） |
| 去重 | 同一风险跨工具/跨轮次归并，避免重复报告 |
| 验证 | 对疑似风险进行二次确认，区分真实风险与误报 |
| 分级 | 按严重程度与影响面将风险分为 CRITICAL / HIGH / MEDIUM / LOW / INFO |
| 基线对比 | 以页面内容哈希等基线比对页面篡改 |
| 复测 | 对已发现风险在修复后进行再次检测确认 |
| 恒脑 | 安恒智能体平台（模型 + 编排 + 工具 + 知识库 + OpenAPI），本项目智能体运行底座 |
| 非破坏性测试 | 不改变目标状态、不触发破坏效果的检测方式 |
