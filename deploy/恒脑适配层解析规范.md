## 2. execute 非流式解析

返回结构：`{code, msg, flag, data{session, results, token_usage}}`

```python
def parse_execute(body):
    r = json.loads(body)
    if r["code"] != 0:
        return AgentResultError(r["code"], r["msg"])
    d = r["data"]
    # session.messages: [{role: user/assistant, content}] 最终对话
    # results: 智能体结构化输出参数（可能为空对象）
    # token_usage: {prompt_tokens, completion_tokens, total_tokens}
    return AgentResult(messages=d["session"]["messages"],
                       results=d.get("results") or {},
                       usage=d.get("token_usage"))
```

## 3. execute 流式（SSE）解析规则

每条 `data:` 行：`{code, msg, data{mode, from, message_id, type, aid, content, node_id, timestamp, done}}`

**解析要点（实测确认）**：

| 规则 | 实测依据 |
| --- | --- |
| 按 `message_id` 分组，`content` 分片拼接 | 同 message_id 的 content 逐字分片（node1/node3） |
| `done:true` 表示该消息结束 | 末条消息带 done 标记 |
| `from` 区分消息来源 | `basic_llm`（模型思考/输出）、`execute_result`（执行结果）、`react_*`、`retrieval_doc_*`、`restful_answer` |
| 前端按 message_id 聚合展示，完成后渲染完整消息 | type=inline 逐字输出 |
| 交互问题消息：`mode="question"` 时需前端渲染问题并调 resume | 见 §5 |

```python
def parse_sse_line(line):
    # line 形如 data:{...}
    payload = json.loads(line[len("data:"):])
    m = payload["data"]
    return {
        "message_id": m["message_id"],
        "from": m["from"],
        "content": m.get("content", ""),
        "done": m.get("done", False),
        "node_id": m.get("node_id"),
        "mode": m.get("mode"),
    }

def aggregate_sse(messages):
    # 按 message_id 聚合分片
    acc = {}
    for m in messages:
        acc.setdefault(m["message_id"], []).append(m)
    return [{"message_id": k, "from": v[0]["from"], "text": "".join(x["content"] for x in v),
             "done": v[-1].get("done", False)} for k, v in acc.items()]
```

## 4. 异步任务轮询状态机（巡检长任务主通道）

```
task/submit({sid, id, inputs}) → data 直接为 taskId（字符串）
task/status({taskId}) → data 直接为状态数值
task/messages({taskId, full}) → data{messages, status}
```

| status | 含义 | 处理 |
| --- | --- | --- |
| 1 | 运行中 | 继续轮询（建议间隔 5s，上限见超时配置） |
| 2 | 完成 | 拉取 messages（full=true 全量）聚合结果 |
| 3 | 取消 | 结束任务，记录取消原因 |
| 4 | 失败 | 读取 messages.errors 定位原因，按错误码映射上报 |

> 实测注意：`task/status` 与 `task/messages` 的 `data.status` 均可能出现；messages 返回的 errors 字段（如 `inputs error: parameter 'xxx' are required`）即传参失败原因，适配层应转成可读错误并提示"检查智能体 inputParameters"。

## 5. 交互回答（execute/resume）

- execute 流式中出现 `mode="question"` 消息（含问题内容、选项、qid/message_id）→ 前端渲染 → 用户回答 → 调 `execute/resume`（messageId + inputs）→ 继续流式；
- 输出参数以 `_question/_options/_answer` 形式回传；
- 本项目场景：巡检授权确认、检测范围确认。

## 6. 错误码映射（恒脑 → 项目）

| 恒脑 code | 含义 | 项目错误码（SDD-03） | 处理 |
| --- | --- | --- | --- |
| 0 | 成功 | — | — |
| -402 | 认证失败（时间偏差/签名） | 40310 | 校验服务器时间（NTP），重签 |
| -403 | 权限不足 | 40310 | 检查 appKey 授权范围 |
| -405 | 不支持的方法 | 40310 | 检查接口 method（agent/* 为 POST；system/*、document/* 部分为 GET） |
| -409 | 参数校验失败（如智能体 id 为空） | 40010 | 按提示修正参数 |
| -504 | 输入参数缺失（inputs error） | 40010 | **先查智能体 inputParameters 再传参**（get_agent_detail.py） |
| -304 | 今日调用次数达限 | 50002 | 限流退避，次日恢复 |
| -301/-300 | 并发/连接超限 | 50002 | **排队重试（并发上限 3）** |
| -200 | AI 引擎出错 | 50001 | 降级/重试 |
| -500/-502/-503/-504 | 服务端异常 | 50001 | 重试（flag=2 时停止等待） |

## 7. 限速参数定标（并发配额实测）

`system/info` 实测：**全部相关接口并发配额 = 3**（智能体执行 v2、智能体异步执行 v2、RAG 检索/问答、大模型问答均如此）。

| 场景 | 限速参数建议 |
| --- | --- |
| 巡检任务调度 | 异步任务并发 ≤2（预留余量，避开 3 上限触发 -301） |
| 对话（execute 流式） | 单会话串行，全局并发 ≤2 |
| RAG 检索（知识库） | 批量检索串行，并发 ≤2 |
| 报告生成 | 与巡检错峰执行 |
| 限流退避 | -304 当日停止重试；-301/-300 指数退避（1s/2s/4s）上限 5 次 |

> token 额度：free=1,000,000（有效期至 2026-12-31，当前 used=0）；用量卡（`tenant/usage/statistics`）用于审计页展示与接近限额预警。
