### 授权登记不能混淆的字段

- 本表登记的是**精确 origin（协议、主机、端口）及路径**；A–E 五个端口不能相互替代，`localhost` 也不自动等于 `127.0.0.1`。
- 数据库 `auth_scope.domain` 是唯一的纯主机名，不接受协议、端口、路径。因此不能将五个 `127.0.0.1:端口` 填进 domain，也不能建五条重复的 `127.0.0.1` 记录。
- 离线样例的 `AuthorizedScope("fixture-d", "http://127.0.0.1:18084", "/")` 是 T20 的输入授权对象，不是已落库的用户资产授权。`fixture-d`、样例 Finding ID、测试管理员均不能冒充真实业务 ID/账号。
- 在线演示前由 B/C 确认资产 ID 与精确 origin/路径的可信映射，并由 B 提供用户到资产的授权映射；若改用独立域名，须同步 F 的样例版本与授权基线。不能通过“授权整个回环地址所有端口”绕过待定映射。当前本文不声称已录入线上资产。

登记至少留存：环境所有者、获准 origin/路径、允许操作/时间、授权依据、业务 scopeId、运维账号及复核人；实际值由演示环境负责人填写，不能从请求体信任导入。

## 5. 从干净演示环境启动

以下为 PowerShell 命令，均从仓库根目录开始。使用专门的演示副本和数据库；已有 `.env` 不覆盖，先由负责人确认配置归属。命令块中的独立终端不要互相关闭。

### 5.1 安装与专用配置

```powershell
$env:PYTHONUTF8='1'
if (-not (Test-Path -LiteralPath '.venv/Scripts/python.exe')) {
    python -m venv .venv
}
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

启动前在**专用演示副本**中设置上表配置，修改模板默认密钥/初始口令，确认平台凭据为空。已有业务 `.env` 不直接改作演示用。安装若遇 python-Wappalyzer 依赖构建问题，按 `requirements.txt` 中的现有说明处理；不要为演示现场随意升级版本。

### 5.2 后端与角色账号

终端 1（进程环境覆盖确保使用专用 SQLite）：

```powershell
$env:APP_ENV='dev'
$env:DATABASE_URL='sqlite+pysqlite:///./.local/demo-t47.db'
$env:API_PREFIX='/api'
.\.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

终端 2 使用同一专用配置创建运维/规则账号，密码经隐藏输入设置；同名账号已存在会拒绝而不是覆盖。`admin` 在上述首次启动时创建，无需重复执行创建命令。

```powershell
$env:APP_ENV='dev'
$env:DATABASE_URL='sqlite+pysqlite:///./.local/demo-t47.db'
.\.venv\Scripts\python.exe scripts/create_user.py demo-ops --role SEC_OPS --nickname 演示运维
```

健康响应应为 code=0、data.status=up。打开 `http://127.0.0.1:8000/docs`；实际业务路径仅有 health、auth/login、auth/me、auth/logout、auth/password、agent/logs，不能把未挂载的资产/告警/复测/报告接口返回 404 当成演示成功。登录、退出、角色演示沿用 [B 的 T49 流程](../docs/02-质量与验收/T49-B组演示流程与答辩材料.md)。

## 8. 停止、排错与验收

| 现象 | 核查/处理 |
| --- | --- |
| 后端起不来或依赖缺失 | 核对实际 Python 与安装依赖的 Python 是否一致、`APP_ENV`、专用 DB 路径；不展示含凭据的连接串 |
| 改了 DEV_ADMIN_PASSWORD 仍登不上 | 变量只在首次创建时读取；由合法账号改密或按管理流程恢复，不清空已有数据库 |
| 401 / 403 / 40310 | 分别核对身份有效性、角色、资产授权/启停；不通过伪造 X-Role 或开放所有 scope_ids 解决 |
| 404 或浏览器跨域 | 核对主分支是否真的挂载业务接口；跨域由 E/B 装配，不能当作“无数据” |
| `/.env` / `/backup.bak` 返回不符 | 核对端口 18084、服务身份和虚拟路径映射，不能改成物理文件路径冒充检测输入 |
| Docker 客户端在而 DVWA 不通 | 先确认引擎、容器、回环端口和初始化状态；本次引擎不可达，8080 无监听 |

停止自己启动的后端和样例服务用对应终端 Ctrl+C；不要停止他人的端口占用进程。若曾启动自己管理的 DVWA，核对归属后可 `docker stop dvwa`，不执行 `docker rm` 或清理卷。保留复现记录，密钥/私有数据库不入包。
