# 恒脑编排设计方案（网站安全智能巡检 Agent，T27）· 手动搭建指导

> 状态：v2.0（2026-10-11，重写为纯手动搭建版；弃用"智能体导入"路线）
> 依据：恒脑平台编排能力（`deploy/恒脑平台文档/07-平台编排操作要点.md`）+ 平台导入格式答复（`hengnao_import_format_answers.md` 关键修正）+ 能力清单
> 执行方式：路径 B——纯平台可视化操作（/development），不依赖开放接口凭据，不使用导入 JSON
> 配套：发布后生成智能体 ID 供后续开放接口调用

## 1. 编排目标

在恒脑平台上手动构建"网站安全智能巡检 Agent"：用户提供授权域名并确认授权后，智能体自主完成
**页面发现 → 安全检测（漏洞/SSL/敏感信息） → 结果汇总**，输出可解释的风险项（证据、影响、修复建议），全程非破坏、可跟踪。

- 智能体名称建议：`网站安全巡检Agent`
- 输入：`target_url`（授权域名，交互节点收集）、`scope`（范围：首页/全站，默认全站）、`check_types`（可选：ssl/vuln/sensitive/tamper）
- 输出：风险项列表（findings）+ 分级统计

## 2. 工作流节点拓扑（3 个画布节点）

```
[交互节点·授权确认] → [自规划节点·巡检执行] → [代码节点·结果聚合]
```

| 节点 | 作用 | 关键配置 |
| --- | --- | --- |
| node0 交互节点 | 收集授权目标 + 授权确认（非破坏合规） | 填空收集 target_url；单选授权确认（确认/取消） |
| node1 自规划节点 | **核心**：自主规划并编排 MCP/技能 | 模型选 **≥128K 上下文**（推荐 GLM-5.1）；MCP/Skill 在自规划节点配置 |
| node2 代码节点 | 结果归一化/去重/分级（轻量） | Python；输入取自规划节点输出；输出 findings + 分级统计 |

> 开始/结束由平台根承载：根输入参数 = 非必填 `input`；结束输出 = 根 output_expression 渲染报告。
> Phase 1 用平台 MCP + 知识库 + 代码节点跑通闭环；篡改/挂马检测等能力服务接口注册后，在自规划节点后追加"插件节点"（见 §8 Phase 2）。

## 3. 手动搭建步骤（/development 操作）

### 3.1 新建智能体

1. 登录 `https://www.das-ai.com` → 进入 `/development`（智能体编排）；
2. 「新建智能体」→ 选 **智能体应用 · 低代码**（不要选零代码/自规划整体形态/组合）；
3. 填写名称 `网站安全巡检Agent`、描述（≥8 字，写清"对已授权网站做非破坏性安全巡检"）；
4. 开场白（prologue）写一句 ≥8 字的说明。

### 3.6 连线与结束

- 连线：`node0 → node1`、`node1 → node2`（串行单线，无条件边）；

### 3.7 调试与发布

1. 画布右上角「调试」：输入授权目标 → 触发交互确认 → 观察自规划调用链 → 检查 node2 报告；
2. 调试通过后「发布」→ 选择发布范围（建议"同租户"或"仅自己"，勿公开公网）；
3. 发布后记录生成的**唯一智能体 ID**（"我的创建"中未发布智能体不可被开放接口调用，务必发布）。

## 4. 关键配置模板（直接复制使用）

### 4.1 自规划节点系统提示词

```
你是网站安全智能巡检 Agent。你只对被明确授权且经人工确认的域名执行安全巡检，全程非破坏：
只做只读检测与模板化扫描，禁止利用、注入、爆破、绕过认证，禁止向未授权目标发起请求。

巡检流程（按顺序自主规划执行）：
1. 页面发现：调用子域名发现 / 证书透明查询 MCP，结合 target_url 与 scope 确定巡检目标清单；
2. 传输安全：调用 SSL/TLS 检测 MCP，检查证书有效性、协议版本与弱配置；
3. 漏洞检测：调用 Nuclei 漏洞扫描 MCP（模板化、非利用），识别常见漏洞与弱配置；
4. 敏感信息：基于安全巡检知识库（RAG）比对，检查页面/资源中可能暴露的敏感信息模式；
5. 结果汇总：对发现项给出 风险等级、证据、影响说明、修复建议。

输入参数：target_url（授权域名）、scope（首页/全站）、check_types（ssl/vuln/sensitive 等）。
输出要求：每个风险项必须包含 evidence（证据摘要，敏感信息需脱敏）、impact、recommendation、
severity（high/medium/low）。无法确认授权的目标一律先请求人工确认，不得直接扫描。
```

### 4.2 交互节点问题配置

| 配置项 | 值 |
| --- | --- |
| 问题 1 名称 | `target_url`（填空） |
| 问题 1 内容 | `请提供已授权巡检的目标地址（如 http://127.0.0.1:8080）与巡检范围说明：` |
| 问题 2 名称 | `authorize`（单选） |
| 问题 2 内容 | `已记录授权目标，请确认是否对该目标发起非破坏性安全巡检？` |
| 选项 | A=`确认授权，开始巡检`；B=`取消巡检` |

### 4.3 代码节点（Python）

```python
import json

def handler(args):
    raw = args.input.scan_result
    try:
        data = json.loads(raw) if isinstance(raw, str) else (raw or {})
    except Exception:
        data = {}
    findings = data.get("findings") or []
    # 去重
    seen, uniq = set(), []
    for f in findings:
        key = str(f.get("type")) + "|" + str(f.get("url")) + "|" + str(f.get("detail"))
        if key not in seen:
            seen.add(key)
            uniq.append(f)
    # 分级
    level_map = {"high": "高危", "medium": "中危", "low": "低危", "info": "信息"}
    counts = {"高危": 0, "中危": 0, "低危": 0, "信息": 0}
    for f in uniq:
        lv = level_map.get(str(f.get("level", "info")), "信息")
        f["level_cn"] = lv
        counts[lv] = counts.get(lv, 0) + 1
    report = {"total": len(uniq), "counts": counts, "findings": uniq}
    return {"result": json.dumps(report, ensure_ascii=False, indent=2)}
```

> 代码节点入参只能写 `args.input.<参数名>`（写 args.scan_result 之外的字段会运行报错）。

## 7. 验证用例（平台上直接对话测试）

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| 授权确认 | `对 http://127.0.0.1:8080 做安全巡检` | 触发交互节点问题，未确认不扫描 |
| 确认后巡检 | `确认授权，开始巡检` | 自规划节点依次调用发现/SSL/Nuclei，输出风险项清单（含 evidence/impact/recommendation/severity） |
| 范围约束 | `只检测目标首页 SSL` | 仅执行 SSL/TLS 检测，不扩散 |
| 非破坏校验 | 任意输入 | 不出现 SQLmap/SSH 等破坏性工具调用 |

### 7.1 验收对照（赛题 5 项评分）

- 功能完整性（25%）：资产发现/检测/敏感信息/输出闭环在编排中可见；
- 检测效果（30%）：Nuclei 模板 + SSL + 知识库比对产出真实风险项（本地授权靶场 `http://127.0.0.1:8080` 已就绪）；
- 智能体能力（20%）：自规划节点自主拆解流程、按需调用 MCP、结果带证据与建议；
- 安全合规（10%）：交互授权确认 + 白名单 MCP + 非破坏提示词；
- 工程化与创新（15%）：发布后开放接口可调用、可与能力服务协同扩展。

## 8. Phase 2 扩展（能力服务就绪后）

能力服务开发完成后，编排追加：
1. **API 工具注册**：将能力服务接口（篡改检测、敏感信息检测、报告生成）注册为 API 工具能力项（调试通过后才能在编排选中）；
2. 自规划节点后追加**插件节点**：调用"篡改检测能力项""敏感信息检测能力项"；
3. 结束节点引用报告生成能力项输出；
4. 形成完整"发现→检测→聚合→报告"闭环。
