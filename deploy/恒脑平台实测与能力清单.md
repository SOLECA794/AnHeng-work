### 2.7 智能体参数 schema 差异（实测关键发现）

不同智能体的 `inputs` 参数定义不同，**调用前必须先查该智能体 inputParameters 并按 schema 传参**（`scripts/get_agent_detail.py`）：

| 智能体 | inputs 要求 | 场景说明 |
| --- | --- | --- |
| 恶意IoC查询 | 仅 `input`（自然语言） | 域名/IP/哈希威胁情报，实测可用 |
| 通用行业数据分类分级 | `table`/`table_description`/`field`/`field_description`/`field_example`/`all_fields`/`frame`（全部必填） | 表结构字段分类场景，**与文本敏感信息场景不对口**，复用需谨慎 |
| 告警研判 | 需 `toolName` 等 | 告警上下文相关参数 |

> 工程影响：恒脑适配层（AgentProvider）必须支持"先查 schema、按 schema 构造 inputs"的通用传参机制，不能假设统一参数（对应 SDD-01 §5.2）。

### 2.8 知识库开放接口（T06 实测关键发现）

- **`document/upload` 的 `sourceId` 是自定义来源标识，不是平台 UI 知识库 ID**：实测传任意字符串（如 `sensitive-rules`）均成功；-103 仅因缺该字段；
- 开放接口 document/*（upload→status→retrieve）**独立于平台"安全知识库管理"UI 可用**，是"脱离平台绑定"的又一路径：知识库能力可由能力服务直接实现；
- retrieve 实测：不传 sourceId 时全局检索（返回多个来源命中），返回 `sourceId/fileName/pageNumber/chunkId/chunkContent/score/rerankScore/md5`；可支撑敏感规则语义匹配；
- 平台 UI 知识库仍服务于 T27 编排（智能体节点"知识库配置"需在平台勾选），两者并存。

## 4. 工具白名单评估建议（平台 MCP）

按赛题"合规开源工具 + 非破坏 + 授权边界"原则，对平台 MCP 建议三档：

| 档位 | 判定 | MCP | 处置 |
| --- | --- | --- | --- |
| ✅ 可纳入 | 被动/只读、非破坏 | Nuclei（模板检测）、SSL/TLS 检测、证书透明查询、子域名发现、DuckDuckGo/多引擎搜索、时间感知、文档转 Markdown、数据处理 | 纳入编排白名单，配置限速与授权范围 |
| ⚠️ 评审后 | 主动探测，需严格限速+授权 | Nmap、Masscan、Amass、HTTP 参数发现、Web 模糊测试、WordPress 安全检测、流量包分析 | 逐项评审，默认不启用，需要时走工具准入流程 |
| ❌ 禁止 | 破坏性/注入/远程执行 | SQLmap 注入检测、渗透测试工具集、SSH 远程命令、MySQL 安全交互、Webhook/钉钉/企微消息 | 赛题非破坏原则下禁止纳入；如演示需要走明确授权与评审 |

> 注：上述为**建议**，最终白名单以组内评审为准；平台 MCP 与自研 `tools/` 适配器是两条可并行路径，平台 MCP 服务于恒脑编排侧，自研适配器服务于能力服务侧（可脱离平台）。
