# T42 检测效果评估口径与执行说明

状态：评估工具与报告结构已就绪；真实检测链路尚未在本文件中执行。依据 `TEST-01` §2.3/§3 T2 和 `tests/dataset/v1.0.0.json`。本文件只规定如何算分，不预填任何检测成绩。

## 评估对象

一个样例 ID 对一个指定 `category` 是一个判定单位。例如 B-02 与 B-04 虽指向同一个 `/about.html`，仍分别验证恶意外链和挂马脚本；E 的 `/` 同理。只有指定类别的实际 Finding 才使该单位 `detected=true`。同一单位即使有多条同类 Finding，也只计一次，但所有 Finding ID 要保留作证据。

| 用例 | 样例与类别 | 当前正例/负例 |
| --- | --- | --- |
| TC-E1 漏洞与弱配置 | A-01、A-03、E-01（`VULN`）；A-02、E-05（`WEAK_CONFIG`） | 2 / 3 |
| TC-E2 外链与挂马 | B-01、B-02、E-02（`MALICIOUS_LINK`）；B-03、B-04（`MALICIOUS_SCRIPT`） | 2 / 3 |
| TC-E3 篡改 | C-01、C-02（`TAMPER`） | 1 / 1 |
| TC-E4 敏感信息 | D-01～D-03、E-04（`SENSITIVE`） | 3 / 1 |
| TC-E5 正常站点 | E-01、E-05、E-02、E-04 | 0 / 4 |

全量为 16 个判定单位：正例 8、负例 8。E 站点只有 4 个负例，没有 `MALICIOUS_SCRIPT` 和 `TAMPER` 标签；这两类的负例分别由 B-04 和 C-02 承担。A 的 HTML 反射样例只代表本测试集中的 `VULN`，不能推广为已知 CVE 召回率。

## 四格表与结论边界

| 真值 / 实际 | 命中 | 未命中 |
| --- | --- | --- |
| 正例 | TP | FN |
| 负例 | FP | TN |

- 召回率 `TP/(TP+FN)`；准确率（Precision）`TP/(TP+FP)`；主误报率（负例命中比例）`FP/(FP+TN)`；补充的告警中误报占比 `FP/(TP+FP)`。分母为零显示 `N/A`。
- `blocked` 和 `not_run` 均不进入 TP/FN/FP/TN。覆盖率为 `executed/total`；覆盖不全时报告标记 `partial`，只能说明已观察样例的数值，不得写“整体达标”。
- 在报告某类别“零命中/无误报”前，先确认同轮、同配置的已知正例能命中。若没有命中的正对照，评估脚本会给出警告；这时即使负例全部无告警，也不能断言检测器有效。
- 分组结果包含四类汇总，报告同时列六个原始类别和 E 站点负例。T42 没有自动通过阈值；最终验收结合覆盖、配置、证据与规格人工判断。

## 采集与复算

在仓库根目录先生成一轮输入文件：

```powershell
python scripts/evaluate_t42.py --init-input reports/t42-run-001-input.json
```

仓库内的 [`T42-result-input-template.json`](T42-result-input-template.json) 是当前 16 条样例的空白模板；也可用上面的命令按当前样例文件重新生成。填写 `run_id`、`code_commit`、`scan_config`，再逐条将 `status` 设为 `executed`、`blocked` 或 `not_run`。已执行项的 `detected` 必须为布尔值，`evidence` 至少有一个**脱敏证据路径或可追踪任务 ID**；命中时尽量附该类别的 `finding_ids`，未命中时该字段应为空。阻塞项须写 `reason`，且 `detected` 保持 `null`。`scan_config` 至少记录工具及版本、规则/模板版本、黑名单、限速、靶场入口和基线版本；不要写凭据或真实敏感内容。样例文件的 `dataset_sha256` 由脚本生成，变更样例后须重新生成输入文件。

`detected` 应来自**实际执行链路**的 Finding 列表：按样例的宿主页面和类别匹配，去掉同一风险的重复结果。部分检测器的 `finding.url` 指向外部恶意资源，此时应根据 Finding 的“所在页面”证据或来源页面字段关联样例，不要直接把资源 URL 当作样例页 URL。不要拿只构造命令的输出代替实际执行结果。对 C 类使用登记的基线版本；对 `.invalid` 域名只做页面内容解析，不请求这些外部地址。

填写后复算：

```powershell
python scripts/evaluate_t42.py --input reports/t42-run-001-input.json --json-out reports/t42-run-001-metrics.json --markdown-out reports/t42-run-001-report.md
python -m unittest tests.unit.test_evaluate_t42
```

脚本校验 16 个样例 ID 无遗漏或重复、版本与 SHA 一致、状态和证据齐全；再生成含逐例证据、四类汇总及限制说明的报告。若某项没跑到，照实标记阻塞/未执行，不推断为“未命中”。原始接口输出或日志可另存脱敏文件并在 `evidence` 中引用；本脚本不发网络请求，也不启动扫描。

## 当前依赖

实际计分需要 C/D 检测器及结果链路合并、可访问的授权本机 A～E 靶标，以及逐例实际 Finding 证据。公网授权目标首跑与 T40 固定样例集分开统计，不能把一次公网扫描代入这 16 条的分母。样例集内容若修改，应发布新版本并固定文件 SHA。
