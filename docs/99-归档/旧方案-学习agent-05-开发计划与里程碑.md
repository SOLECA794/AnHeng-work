# 05 · 开发计划与里程碑

> 说明：按需求方要求，本文档**不含时间排期与人员分工**，只给出开发顺序、模块划分、验收标准与开发规范。

## 1. 开发顺序总览

依赖关系决定开发顺序，原则：先地基后业务、先闭环后扩展、先能力后应用。

```
阶段 A（地基）：能力服务骨架、认证鉴权、统一响应、恒脑编排适配层接入、MCP 工具框架
阶段 B（知识底座）：考纲图谱、知识点、题库、资料向量化与检索
阶段 C（计划引擎）：目标解析、计划生成、任务管理
阶段 D（学习闭环）：出题、判分、错题归因、复习调度、掌握度
阶段 E（Agent 对话与语音）：意图识别、工具编排、SSE 流式、语音链路
阶段 F（跨端应用）：ArkUI-X 工程、页面、本地存储、语音接入
阶段 G（收尾）：联调、测试、演示数据、部署与文档
```

能力服务按 04 文档实现，应用端按同文档联调；同一阶段内两端并行开发，能力服务先出接口，应用端可用 Mock 先行开发页面。

## 4. 里程碑与验收标准（按阶段，无时间排期）

| 阶段 | 里程碑成果 | 验收标准 |
| --- | --- | --- |
| A 地基 | 能力服务可启动，恒脑编排可调用，MCP 工具框架可用 | 认证/鉴权/统一响应通过；恒脑 API 连通性验证；工具注册与审计埋点生效 |
| B 知识底座 | 考纲图谱、题库、资料检索可用 | 图谱树浏览正确；向量检索返回相关结果；初始化脚本可执行 |
| C 计划引擎 | 目标 → 计划 → 任务闭环可演示 | 目标解析可确认；任务序列生成幂等；任务状态流转正确 |
| D 学习闭环 | 出题 → 判分 → 错题 → 复习 → 掌握度闭环 | 判分正确；错题自动归因不重复；复习项按间隔生成；掌握度更新符合规则 |
| E Agent 与语音 | 自然语言指令完成学习任务；语音链路可用 | 典型指令（"今天复习计组第三章"）全流程跑通；工具轨迹可见；ASR→TTS 链路通 |

| G 收尾 | 演示环境、文档、演示数据齐备 | 演示账号/数据/流程可用；文档与实现一致；关键缺陷关闭 |

## 6. 开发规范（执行细则）

### 6.1 Git 与分支

- 分支：`main`（稳定可演示）、`dev`（集成分支）、`feature/xxx`（功能分支）、`fix/xxx`（缺陷分支）；
- 流程：从 `dev` 拉取功能分支 → 开发与自测 → 合并请求 → 评审合并到 `dev`；阶段完成合并 `dev → main`；
- 提交信息：`类型: 内容`，类型含 `feat` / `fix` / `docs` / `refactor` / `test` / `chore`；
- 合并前完成自测与冲突处理；禁止直接向 `main` 提交开发代码。

### 6.2 代码规范

- 能力服务：Python 3.11 + FastAPI；包结构见 02 文档；禁止路由层直连数据库；业务规则放 services；
- 应用端：ArkTS + ArkUI 声明式；组件大驼峰、方法小驼峰；API 集中 services 目录，页面不散写请求；
- 统一命名：时间字段 `xxxTime`/`xxxAt`、状态字段语义值大写、工具名小写点分（`task.today`）。

### 6.3 接口规范

- 遵循 04 文档统一响应与错误码；字段变更同步 Apifox 与本文档；
- 写接口必须做参数校验与角色校验；Agent 对话接口限流。

### 6.4 数据库规范

- 遵循 03 文档约定；脚本纳入版本管理；结构变更走增量脚本并评审。

### 6.5 文档规范

- 标题层级、图表编号、术语统一；需求变更同步更新本文档集、接口文档与测试文档。

### 6.6 测试规范

- 核心功能覆盖正常、边界、异常、越权四类场景；缺陷保留复现步骤与修复记录；
- 重点测试：计划生成幂等、判分正确性、错题唯一约束、复习间隔、语音链路、跨端一致性。
