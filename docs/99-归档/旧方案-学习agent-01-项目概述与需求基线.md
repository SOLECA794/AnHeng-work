# 01 · 项目概述与需求基线

## 1. 课题信息

| 项 | 内容 |
| --- | --- |
| 课题名称 | Learning Agent · 408 考研学习智能体 |
| 团队定位 | 面向计算机考研学生（408 四科）的 AI 学习过程管理助手；以"计划驱动"为核心闭环，跨端（HarmonyOS / Android）可用的 Agent 应用 |
| 交付形态 | 鸿蒙 + Android 双端跨端应用（ArkUI-X）+ 云端能力服务 + 智能体底座（恒脑平台） |

## 2. 项目背景

计算机考研（408：数据结构、计算机组成原理、操作系统、计算机网络）备考周期长、科目多、知识点分散，学生普遍存在以下问题：

1. **计划难坚持**：学习计划停留在"写在纸上/脑中的粗略目标"，缺少按知识点粒度拆解、可执行、可追踪的机制；
2. **复习无节奏**：学完就忘，缺少基于遗忘曲线的复习调度，"学了前面忘后面"；
3. **错题分散**：错题散落在练习册、电子笔记、聊天记录中，无法归因到具体知识点，也无法反哺复习计划；
4. **资料碎片化**：教材、讲义、真题、视频分散在多处，缺少统一的、按考纲组织的知识入口。

市面上已有大量"答疑/讲解类"学习工具，但普遍停留在"单次问答"，没有解决"学习过程管理"的问题——学什么、什么时候学、学得怎么样、忘了没有。

本项目定位为**学习过程管家而非答疑工具**：以 408 考纲知识图谱为基础，以计划驱动为主线，提供目标拆解、每日任务、出题验证、错题归因、间隔复习、进度追踪的完整闭环，并通过 Agent 的自然语言交互与语音能力降低使用门槛。

## 3. 项目核心目标

1. 建立 408 考纲 → 知识点 → 题目/资料的三层知识结构，形成可检索、可追踪的知识底座。
2. 实现"目标设定 → 计划生成 → 每日任务 → 学习执行 → 出题验证 → 错题归因 → 复习调度"的完整学习闭环（计划驱动）。
3. 提供自然语言 + 语音的 Agent 交互：用户以一句话下达学习指令，Agent 自主完成计划查询、任务推进、出题、反馈等动作。
4. 实现 HarmonyOS / Android 跨端应用（一套代码），文本对话两端必做、鸿蒙语音（ASR→模型→TTS）必做，会话本地持久化。
5. 能力层与平台解耦：智能体编排基于恒脑平台实现，同时保证工具、知识库、数据可脱离平台迁移（平台无关设计）。

## 4. 用户角色与权限边界

| 角色 | 使用端 | 可执行核心操作 | 数据范围 |
| --- | --- | --- | --- |
| 学习者 | 跨端应用 | 设定学习目标、查看/执行每日任务、浏览知识图谱、出题练习、错题复习、语音对话、查看进度 | 本人数据 |
| 内容管理员 | 能力服务管理端 | 维护考纲、知识点、题目、资料；审核用户导入内容 | 知识库数据 |
| 系统管理员 | 能力服务管理端 | 用户管理、日志查询、系统配置 | 全系统数据 |

权限实现要求：能力服务接口按角色鉴权（未登录 401、越权 403）；学习者不可访问管理端；应用端本地数据仅本人可见。

## 5. 功能需求清单

### 5.1 学习目标与计划管理（计划驱动核心）

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 目标设定 | 用户以自然语言描述目标（如"12 月底前完成 408 一轮复习"），Agent 解析为结构化目标 | 解析结果可预览、可修正；目标包含科目范围与截止时间 |
| 计划生成 | 基于考纲图谱将目标拆解为阶段计划（科目 → 章节 → 知识点），并生成每日任务序列 | 计划可按知识点粒度展开；可手动调整 |
| 计划状态 | 进行中 / 暂停 / 已完成 | 暂停后任务停止推进；完成可复盘 |
| 每日任务 | 按日期生成任务列表（学习 / 测验 / 复习三类） | 今日任务可查询；任务完成状态可更新 |
| 任务推进 | 用户执行任务后可标记完成/跳过 | 完成记录时间；跳过不影响计划整体 |

### 5.2 知识库与学习内容

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 考纲图谱 | 展示 408 四科 → 章节 → 知识点的树状结构 | 可逐级浏览；知识点含掌握度标记 |
| 知识点详情 | 知识点内容、关联题目、关联资料 | 详情页可查看；资料可跳转 |
| 知识检索 | 自然语言检索知识点与资料（向量检索） | 返回相关内容与来源 |
| 掌握度模型 | 每个知识点维护掌握度（0–100），由答题与复习反馈更新 | 掌握度随正确答题上升、随遗忘衰减 |

### 5.3 出题练习与判分

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 出题 | 按知识点 / 数量 / 难度从题库抽取题目，或按模板生成 | 题目与知识点关联；难度可指定 |
| 答题判分 | 提交答案后判分并给出解析 | 客观题自动判分；记录答题记录 |
| 答题记录 | 记录每次答题的题目、答案、结果、耗时 | 历史可查 |

### 5.4 错题与复习

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 错题归因 | 答错题目自动归因到知识点并进入错题本 | 错题与知识点关联；自动进入待复习 |
| 错题本 | 错题列表、重做、标记已掌握 | 重做正确可提升掌握度；可标记已掌握 |
| 复习调度 | 基于遗忘曲线（1/2/4/7/15/30 天）与掌握度生成到期复习项 | 到期复习项并入每日任务；复习完成更新掌握度 |

### 5.5 Agent 对话与语音

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 自然语言交互 | 用户以一句话下达学习指令（计划、任务、出题、复习、查询），Agent 自主规划并调用工具完成 | 多轮任务推进可见；工具调用轨迹可追溯 |
| 语音交互 | 鸿蒙端 ASR 识别 → Agent 处理 → TTS 播报 | 语音提问可正确识别并响应；播报清晰 |
| 会话记录 | 对话历史本地持久化，支持回看 | 重启应用后可回看历史会话 |

### 5.6 进度统计

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 学习概览 | 今日任务完成数、连续学习天数、总学习时长 | 数据与明细一致 |
| 掌握度分布 | 各科目 / 章节掌握度可视化 | 图表与掌握度数据一致 |
| 薄弱知识点 | 低掌握度知识点列表 | 按掌握度排序 |

### 5.7 通知（可选基础版）

| 功能点 | 说明 | 验收要点 |
| --- | --- | --- |
| 复习提醒 | 到期复习项提醒 | 站内通知可读 |
| 计划提醒 | 每日任务开始提醒 | 站内通知可读 |

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 跨端 | ArkUI-X 一套代码构建 HarmonyOS 与 Android；核心逻辑不拆多套独立工程；两端文本对话必做，鸿蒙语音必做 |
| 语音 | 鸿蒙 ASR → 模型 → TTS 链路可用；建议 ASR/TTS 统一接口封装 |
| 性能 | 对话响应首 token 时间可接受；题库千级规模内检索流畅；本地会话回看不卡顿 |
| 安全 | 密码加密存储；接口鉴权；敏感数据本地优先；密钥不入库不入包 |
| 可用性 | 移动端适配；关键操作有成功/失败提示；空态与异常有提示 |
| 可迁移 | 工具按 MCP 标准实现；知识库与用户数据自持（自有数据库）；智能体编排层可替换（恒脑 → 其他平台） |
| 可维护性 | 能力服务分层清晰；统一响应结构；Agent 调用审计可追溯；数据库脚本纳入版本管理 |

## 7. 范围边界（本期不做）

- 不做通用答疑为主的产品定位（讲解仅作为学习环节的附带能力）；
- 不做真题全量版权内容（题库为自建原创题 + 用户可导入自有资料；版权合规）；
- 不做社区、社交、组队功能；
- 不做支付与商业化功能；
- 不做 iOS 端（选做加分项）；
- 不做复杂的长期学习报告导出与深度分析；
- 不做智能体平台本身（复用恒脑能力，不自研编排框架）。

## 8. 术语表

| 术语 | 含义 |
| --- | --- |
| 408 | 计算机学科专业基础综合：数据结构、计算机组成原理、操作系统、计算机网络 |
| 考纲图谱 | 408 考纲 → 章节 → 知识点的树状知识结构 |
| 知识点 | 知识图谱的最小学习单元，含掌握度 |
| 掌握度 | 知识点掌握程度量化值（0–100），由答题与复习反馈更新 |
| 计划驱动 | 以学习计划为主线推进学习闭环：目标 → 计划 → 任务 → 执行 → 验证 → 复习 |
| 间隔复习 | 基于遗忘曲线在固定间隔生成复习任务 |
| 工具（Tool/Skill） | Agent 可调用的能力单元，按 MCP 标准实现（出题、计划、错题等） |
| Agent | 能自主规划并调用工具完成任务闭环的智能体 |
| 恒脑 | 安恒智能体平台（模型 + 编排 + 工具 + 知识库 + OpenAPI），本项目智能体底座 |
| 平台无关 | 工具、知识库、数据不依赖特定平台，可迁移替换 |
