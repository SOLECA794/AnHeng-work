# 02 · 系统架构与关键技术设计

## 1. 总体架构

系统由三部分组成：**跨端应用层**（华为组）、**能力服务层**（安恒组，可独立部署）、**智能体编排层**（恒脑平台 + 可替换适配）。

```
┌─ 应用层（ArkUI-X 跨端应用：HarmonyOS / Android）─────────────┐
│  页面：今日计划 / 学习执行 / 考纲图谱 / 错题本 / 进度统计 / 设置    │
│  鸿蒙语音：ASR → 文本 → Agent → TTS（Core Speech Kit 统一封装）  │
│  本地存储：会话历史、离线任务缓存                                 │
└───────────────────────┬──────────────────────────────────┘
                        │ HTTPS / JSON（统一 OpenAPI 风格）
┌───────────────────────▼──────────────────────────────────┐
│ 能力服务层（自研，Docker 部署）                               │
│  API 网关：鉴权（JWT）、限流、统一响应 {code,message,data}      │
│  工具服务（MCP Server）：计划 / 任务 / 出题 / 判分 / 错题 / 复习   │
│  知识库服务：考纲图谱查询 + 向量检索（RAG）+ 掌握度引擎           │
└───────────────────────┬──────────────────────────────────┘
                        │ OpenAPI（对话 + 工具调用）
┌───────────────────────▼──────────────────────────────────┐
│ 智能体编排层：恒脑平台（模型 + 编排 + 多智能体协同）               │
│  编排适配层（本项目定义统一接口，恒脑实现；可替换为 Dify/自研）      │
└───────────────────────┬──────────────────────────────────┘
                        ▼
┌──────────────────────────────────────────────────────────┐
│ 数据层：PostgreSQL（业务 + 知识结构化）+ pgvector（向量检索）      │
│  Redis（缓存 / 会话临时态，可选）；应用端本地存储（会话 / 缓存）     │
└──────────────────────────────────────────────────────────┘
```

分层职责：
- 应用层只做交互展示、本地存储与语音接入，不持有业务规则；
- 能力服务层承载学习业务（计划引擎、题库、错题、复习、掌握度）与工具注册，是**核心业务所在**；
- 智能体编排层负责"理解用户意图 → 规划 → 调用能力服务工具 → 汇总反馈"的 Agent 闭环；
- 知识库与业务数据自持于自有数据库，不依赖平台存储。

| 层次 | 技术 | 版本/要点 |

## 3. 后端能力服务工程结构

工程名：learning-agent-server，包结构：

```
learning-agent-server
├── api              # 路由层：auth / plans / tasks / knowledge / quizzes /
│                    #        mistakes / reviews / stats / agent / admin
├── services         # 业务层：计划引擎、出题服务、判分服务、错题服务、复习调度、掌握度引擎
├── tools            # MCP 工具实现：plan / task / knowledge / quiz / mistake / review / progress
├── orchestrator     # 编排适配层：恒脑 OpenAPI 客户端；统一 Agent 接口
├── knowledge        # 知识库：考纲图谱、向量检索（RAG）、资料管理
├── models           # ORM 模型（与 03 文档表对应）
├── schemas          # 入参/出参（Pydantic）
├── core             # 统一响应、错误码、鉴权、配置、日志
└── db               # 连接、迁移脚本（db/schema.sql、db/data.sql、db/migration/）
```

分层职责：api 只做参数接收与返回；services 承载业务规则与事务；tools 实现 MCP 工具（薄封装调用 services）；orchestrator 只做平台对接，不写业务逻辑。

## 5. 关键设计

### 5.1 学习计划引擎（状态机）

计划（plan）状态：`ACTIVE → PAUSED / COMPLETED`。
任务（task）状态：`PENDING → IN_PROGRESS → DONE / SKIPPED`。

流转规则：
- 目标设定 → 计划生成：按考纲图谱将目标拆解为科目 → 章节 → 知识点，生成任务序列；
- 每日任务：按 `task_date` 生成当日任务（STUDY / QUIZ / REVIEW 三类）；
- 任务完成：标记 DONE 记录完成时间；STUDY 完成触发一次出题验证（可跳过）；
- 复习任务：由复习调度（5.5）到期生成，完成后更新掌握度；
- 计划完成：全部阶段任务完成或目标日期到达后置为 COMPLETED。

时间判定统一以能力服务服务器时间为准，应用端不参与业务时间判定。

### 5.2 Agent 能力与工具清单（MCP 标准）

| 工具 | 功能 | 输入要点 | 输出要点 |
| --- | --- | --- | --- |
| plan.generate | 目标 → 学习计划 | 目标文本、科目、截止时间 | 计划结构、任务序列 |
| plan.query | 查询计划 | 计划 ID / 状态 | 计划详情、进度 |
| task.today | 今日任务 | 日期（默认当天） | 任务列表（含类型/知识点） |
| task.update | 任务状态 | 任务 ID、动作（done/skip） | 更新结果 |
| knowledge.query | 知识点/资料检索 | 查询文本、科目 | 相关知识点与资料（向量检索） |
| knowledge.syllabus | 考纲图谱 | 科目/节点 ID | 树结构 |
| quiz.generate | 出题 | 知识点、数量、难度 | 题目列表（不包含答案） |
| quiz.submit | 判分 | 题目 ID、用户答案 | 对错、解析、得分 |
| mistake.list | 错题查询 | 状态、知识点 | 错题列表 |
| mistake.review | 错题重做反馈 | 错题 ID、是否答对 | 掌握度更新结果 |
| review.due | 到期复习项 | 日期 | 到期知识点/任务列表 |
| progress.summary | 进度概览 | 日期范围 | 完成数、掌握度分布、薄弱点 |

工具实现原则：tools 层薄封装 services 业务方法，工具本身**不持有业务状态**（无状态），全部通过服务层读写数据库；工具签名与平台无关，可在任何支持 MCP 的编排器（恒脑 / Dify / 自研）中注册。

### 5.3 Agent 对话流程（计划驱动闭环）

```
用户输入（文本/语音转文本）
  → 编排层意图识别与规划
  → 调用工具（task.today → knowledge.query → quiz.generate → quiz.submit → mistake.list）
  → 工具结果回灌，编排层汇总
  → 自然语言回复（文本 / TTS 播报）
```

典型交互示例：
用户："今天复习计组第三章"
- 意图：计划/任务类 → 调用 `task.today` 定位"计组第三章"任务；
- 执行：调用 `knowledge.query` 提供知识卡片 → 调用 `quiz.generate` 出 3 道题；
- 反馈：用户提交答案 → `quiz.submit` 判分 → 错题自动归因（`mistake`）→ 更新掌握度 → 生成明日复习项；
- 回复：汇总今日完成情况与明日计划，可 TTS 播报。

失败处理：工具调用失败返回明确原因并降级（如题库为空时提示"该知识点暂无题目，请先录入题库"）；不确定时向用户二次确认，不擅自推进。

### 5.4 知识库三层结构与掌握度模型

```
考纲层：408 四科（数据结构 / 计组 / 操作系统 / 计网）
   ↓
知识点层：章节 → 小节 → 知识点（树状，每节点含掌握度 mastery 0–100）
   ↓
资源层：题目（单选/多选/判断/代码）+ 资料（讲义/笔记/卡片，向量化）
```

掌握度更新规则：
- 答题正确：mastery += Δ（按难度加权，上限 100）；
- 答题错误：mastery 降低并记录错题；
- 间隔复习完成：mastery 提升；
- 到期未复习：mastery 随时间衰减（衰减系数可配置）。

### 5.5 复习调度（间隔重复）

- 初始间隔：1 / 2 / 4 / 7 / 15 / 30 天（艾宾浩斯序列）；
- 掌握度低的知识点缩短间隔，掌握度高的延长；
- 到期复习项在每日任务生成时并入（REVIEW 类型）；
- 复习完成反馈 → 更新掌握度 → 计算下一间隔。

### 5.6 出题与判分

- 出题：按知识点 + 难度从题库筛选；支持模板生成（占位符替换，用于题目不足时）；
- 判分：客观题（单选/多选/判断）服务端自动判分；代码题本期仅人工自评（标记待人工复核）；
- 判分结果写答题记录并联动错题与掌握度。

### 5.7 语音交互链路

```
鸿蒙 Core Speech Kit ASR（语音 → 文本）
  → 文本进入 Agent 流程（同 5.3）
  → 回复文本 → TTS（文本 → 语音播报）
```

语音封装为统一接口（`VoiceService`），应用层不直接依赖具体 Kit 实现；Android 端语音为选做加分项。

### 5.8 恒脑依赖隔离与平台无关设计

| 设计点 | 做法 |
| --- | --- |
| 编排适配层 | 定义统一 Agent 接口（对话 / 工具调用 / 任务执行），恒脑 OpenAPI 为当前实现；切换 Dify / 自研只替换 orchestrator 实现 |
| 工具标准化 | 全部工具按 MCP 协议实现，与平台无关 |
| 数据自持 | 知识库、业务数据、向量库全部部署在自有 PostgreSQL/pgvector，不落恒脑 |
| 模型可切换 | 统一模型 Client，支持恒脑 / DeepSeek / 通义千问切换 |
| 对外接口 | 能力服务暴露统一 OpenAPI，应用层只依赖该接口 |

### 5.9 多端与本地存储

- 应用端本地持久化：会话历史（对话 + 工具调用轨迹）、离线任务缓存；
- 云端为数据权威源：任务状态、掌握度、错题、计划以能力服务为准；
- 断网降级：应用端可查看本地会话与缓存任务，写操作提示"待联网同步"。

### 5.10 会话与审计

- 每次 Agent 对话记录会话（含工具调用轨迹 JSON）；
- 每次工具调用记录审计日志（用户、工具、参数摘要、结果状态、耗时、Token 消耗）；
- 管理端可查询审计日志（系统管理员）。

## 6. 部署架构

```
Docker Compose
├── learning-agent-server   # 能力服务（FastAPI，暴露 /api）
├── postgres + pgvector     # 业务 + 知识库 + 向量
└── redis                   # 缓存 / 限流（可选）

华为应用：ArkUI-X 构建 HAP（HarmonyOS）/ APK（Android），通过 HTTPS 访问能力服务网关
恒脑平台：SaaS（OpenAPI 调用），或私有化部署（待确认）
```

部署要点：
- 配置外置（环境变量）：数据库连接、JWT 密钥、恒脑 API 地址与 Key、模型选择；
- 能力服务网关统一限流与鉴权；生产启用 HTTPS；
- 数据库脚本纳入版本管理，可重复执行。

## 7. 关键风险与对策

| 风险 | 对策 |
| --- | --- |
| 恒脑平台能力边界与开放接口未知 | 编排适配层隔离；Phase 0 做平台能力实测；预留 Dify/自研替换路径 |
| 题库内容不足 / 版权问题 | 自建原创题库 + 用户导入自有资料；出题支持模板生成兜底 |
| 大模型规划与判分不可靠 | 业务规则放能力服务（计划生成、判分等关键逻辑服务端兜底），模型只做意图理解与自然语言组织；不确定时人工确认 |
| 跨端差异（语音/存储/UI） | 语音与存储统一接口封装；两端配置差异化、核心逻辑不拆分 |
| 会话与云端数据不一致 | 云端为权威源；本地缓存只读展示；写操作同步提示 |
| 遗忘衰减误伤计划 | 衰减参数可配置；复习到期可顺延，不强制 |
