# T25 · 复测闭环

> 日期：2026-10-17；责任人：D；依据：SRS-02 F5.4、SDD-10。
> 分支依赖 T24 PR #7；T25 PR 以 `feature/d-t24-alerts` 为目标分支，合并顺序 T24→T25。

## 1. 本次完成

提供两阶段复测服务、SQLAlchemy 仓储、真实 T20 敏感信息离线复测 runner、单风险与按资产有界批量入口，以及执行历史。输入是 Finding ID 和可信鉴权，客户端不能提交检测结论、原始 URL 或角色。

| 检测结果 | 状态变化 | 告警联动 |
| --- | --- | --- |
| 完整成功、原规则无命中 | OPEN/CONFIRMED→FIXED | 同事务记录修复边界 |
| 已修复后再次完整无命中 | FIXED/RETESTED→RETESTED | 保持修复边界，不产生新告警 |
| 原规则仍命中 | →CONFIRMED | 活跃周期去重；修复后新命中开启下一周期 |
| 超时、证据不完整、无适配器、规则变化、旧观测 | 保持原状态 | 不声称修复 |
| 检测期间风险/资产变化 | 拒绝旧结果覆盖 | 记录冲突，要求重新复测 |

RETESTED 在本契约中明确表示“再次复测通过”。未修复的风险始终使用 CONFIRMED，避免 T24 把仍有风险误当已修复。FALSE_POSITIVE 不进入修复复测。

## 2. 如何执行

第一事务检查 SEC_OPS、显式资产授权、启用状态和风险身份，持久化 RUNNING 与请求占用；随后释放事务锁并执行 runner；第二事务重新锁资产和风险、比较业务快照与观测时间，再提交状态、执行历史和告警周期。CLEAN 不改 first_seen/last_seen；MATCH 更新 last_seen。保留原证据及来源，复测的新来源与规则摘要记入执行历史。

`SensitiveRetestRunner` 需要服务端保存的原目标、规则 ID、规则快照及身份绑定，不能从 T21 已脱敏 URL 还原路径。它先校验现行资产范围、目标摘要、规则快照，再调用可信取样器，检查精确 URL、HTTP 200、完整覆盖及新鲜时间，并实际重新执行原 T20 规则。来源 SHA256 对正文与响应头的规范 JSON 求摘要；规则 SHA256 对完整规则快照求摘要，均不导出原文。

生产取样器由上游注入，须遵守超时、授权重定向和完整响应要求；本次取样器只使用本地合成内容。其它检测器尚无专用 runner 时返回不确定，不宣称已执行 Nuclei/ZAP 等在线复测。

## 3. 幂等、并发与失败

请求 UUID 形成执行身份，相同已完成请求返回历史结论并带 replayed=true，不重新检测。当前状态另列 currentStatus，历史 status 不会冒充当前状态。不同请求同时处理同一风险时，后来的请求返回冲突；五分钟未完成的占用可由新请求收回，旧结果晚到不能覆盖新请求。

占用保存在 `Finding.raw_data.retest_pending`，操作历史保存在 AgentLog（action 为 `finding.retest:{id}:{UUID}`）；更新检测记录须保留占用，历史日志须保留以支持幂等。审计或告警写入失败时，第二事务整体回滚，第一事务 RUNNING 仍可追踪，待过期收回。不在未知提交结果时保证“恰好一次”。

复用 T24 `process_transaction` 加入同一事务，未创建嵌套的独立告警提交。原 T24 `process` 行为保持原样，并回归原有接口和事务测试。

## 4. 接口与接入

```python
from src.repositories.retesting import SqlAlchemyRetestRepository
from src.services.retesting import RetestService
from src.api.retesting import create_retest_router

service = RetestService(SqlAlchemyRetestRepository(session_factory), trusted_runner)
router = create_retest_router(service, principal_dependency=authenticated_principal)
# 宿主鉴权和可信目标绑定准备好后显式挂载；默认应用未挂载。
```

- POST `/api/findings/{id}/retest`，SEC_OPS；请求可为空或 `{"requestId":"UUID"}`。
- GET `/api/findings/{id}/retests?limit=50`，SEC_OPS/RULE_ADMIN，查看最近历史（最多 100 条，含 RUNNING 与终态记录）。
- POST `/api/auth-scopes/{id}/retest`，SEC_OPS；支持 requestId、limit（≤20）、afterId；按当前每个风险最新 Finding 分页，逐项独立执行。每个子项由批次 UUID 派生 UUID，错误单独返回；不是冻结的全站作业快照。

真实 JWT、前端按钮、在线采集及平台尚待装配；无可信身份时默认拒绝，伪造请求头无效。
