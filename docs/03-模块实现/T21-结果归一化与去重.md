## 2. 四个函数如何分工

| 函数 | 输入 | 作用 |
| --- | --- | --- |
| `normalize_url(url)` | 完整目标 URL | 规范化用于风险身份的 URL |
| `normalize_finding(source, *, task_id, scope_id, tool_name, seen_at, evidence_feature=None, identity_url=None)` | Mapping/dataclass 风险及可信运行上下文 | 字段映射、脱敏输出、生成风险键与初始来源记录 |
| `deduplicate_findings(findings, *, existing=())` | 本轮标准结果及调用方提供的历史结果 | 按资产与风险键归并，更新时间及出现次数 |
| `to_orm_values(record)` | 标准结果 | 映射现有 ORM 字段，返回构造/更新值 |

来源字段接受 `type`/`finding_type`/`findingType` 和 `raw`/`raw_data`/`rawData`；同时出现且相互矛盾的值会被拒绝。时间输入为字符串或 `datetime`，带时区输入转为上海时间，按秒输出无时区时间字符串，无时区输入按上海本地时间使用。任务、资产与工具身份由调用方明确指定，不能依赖外部工具自行声明运行上下文。

无效输入抛出 `FindingValidationError`；资产指纹抛出其子类 `NonRiskFindingError`，供调用方区分并分流。

风险类型覆盖 `VULN`、`WEAK_CONFIG`、`MALICIOUS_LINK`、`MALICIOUS_SCRIPT`、`TAMPER`、`SENSITIVE`。Wappalyzer 的 `FINGERPRINT` 是资产信息，须走独立路径。现有 T19 已产生 `MALICIOUS_SCRIPT`，SDD-02 的枚举文字仍待上游同步；现有 ORM 字符串列可容纳该类型，T21 不进行模型迁移。

## 3. 风险身份与安全展示

身份 URL 与用户看到的 URL 分开处理。身份 URL 统一协议/主机大小写与默认端口，处理 IDNA 主机、非保留字符的百分号表示及点路径段，保留重复斜杠和末尾斜杠的区别。去掉 fragment，按参数名排列查询参数；同名参数的重复值保持原顺序，避免误合请求。`normalize_url` 本身返回完整身份 URL，其返回值不应直接写到展示或日志中。

`dedup_key` 依据 SDD-01 的 MD5 方案，将目标标识、风险类型与规范化特征的 SHA-256 摘要组成 JSON 数组后计算。目标相同但类型或证据特征不同，应保留为不同风险。MD5 只服务于去重，不承担安全校验。

展示结果只保留 origin；根路径显示 `/`，非根路径统一为 `/[REDACTED_PATH]`，不显示查询参数或 fragment。原始工具的标题、证据、影响及建议不回显；类型对应固定安全说明，证据显示 `[REDACTED] (sha256=<digest>)`。完整 Nuclei 输出、请求与响应等原文不会进入 `raw`。

`raw` 只保留 `identity`、`source_sha256`、`observations`，分别记录身份摘要、完整输入摘要与工具/任务/页面/时间及来源摘要。`raw.identity.target_sha256` 支持在隐藏 URL 路径和参数后继续区分目标。真实资源定位依赖可信 `page_id`、目标摘要及受控来源记录。这是保守的输出策略，不宣称能识别任意自由文本中的所有敏感信息。

T20 输入可携带 `raw_data.target_sha256`，用于关联已脱敏的原始目标。摘要无法恢复已经删除的参数及其排序；需要完整规范化时，由调用方显式提供 `identity_url`。该参数用于风险身份，不替代检测入口的授权范围检查。

## 4. 跨工具和跨轮次如何归并

跨工具的语义相同不能仅靠不同工具的标题判断。调用方可以为对应风险提供共享的 `evidence_feature`，例如同一缺失安全响应头的名称与位置；特征一致、目标一致、类型一致时才得到同一键。

没有显式特征时使用当前工具的稳定标识：Nuclei 模板与 matcher、ZAP pluginId 与参数、T19 rule_id、T20 rule_id 与位置及规则类型。若这些结构缺失，可使用非空且未脱敏的证据文本计算摘要，原文不输出。回退特征包含可信工具名，因此不同工具都使用 `rule001` 时保持分离；只有显式共享 `evidence_feature` 才启用跨工具语义归并。敏感结果若只有通用 `[REDACTED]` 文本且缺少结构化规则标识，则拒绝处理，避免不同敏感风险碰撞。

归并分组使用 `(scope_id, dedup_key)`，不同授权资产保持隔离。`first_seen` 取最早值，`last_seen` 取最新值；按 SDD-01 保留最早记录的严重级别，`task_id` 对应最早观测。T21 不自动调整分级，级别策略由 T23 负责。`occurrence` 统计不同 `task_id`：同一任务重试、多工具重复命中或重复输入只算一次。

已有历史记录的 ID 与 `CONFIRMED`、`FALSE_POSITIVE`、`FIXED`、`RETESTED` 等状态保持原值。是否重开风险、是否确认为误报或修复由 T22/T25 负责；T21 不替代状态机。

调用方必须提供 `existing` 历史，才能完成跨轮次归并。仅传本轮结果时不会自动查询历史或持久化。归并不原地修改输入，并保存来源摘要以复核对应工具与任务。同任务、工具、页面及输入摘要相同的重试合为一次观测，保留最新时间；风险记录的首次发现时间仍保留最早值。

当前结果与 `existing` 都必须是符合 T21 安全结构的标准记录。字段白名单拒绝未知 `raw` 内容、被改写的自由文本及不一致的出现次数/时间/来源；历史可额外携带已有数据库 ID。普通 ORM 行或旧版原始记录不能直接传入，需要上游另外实现安全的历史适配。这样可以避免在归并历史时把过去存储的原文再次导出。

## 5. 最小调用示例

```python
from src.services.findings import normalize_finding, deduplicate_findings

feature = {"kind": "missing_header", "header": "x-content-type-options"}
source = {
    "finding_type": "WEAK_CONFIG",
    "severity": "MEDIUM",
    "url": "https://demo.example.invalid/status?a=1&b=2",
}
first = normalize_finding(
    source, task_id=101, scope_id=1, tool_name="nuclei",
    seen_at="2026-10-13T09:00:00+08:00", evidence_feature=feature,
)
same_task = normalize_finding(
    source, task_id=101, scope_id=1, tool_name="zap-passive",
    seen_at="2026-10-13T09:01:00+08:00", evidence_feature=feature,
)
history = deduplicate_findings([first, same_task])

next_round = normalize_finding(
    source, task_id=102, scope_id=1, tool_name="nuclei",
    seen_at="2026-10-14T09:00:00+08:00", evidence_feature=feature,
)
merged = deduplicate_findings([next_round], existing=history)
```

示例中两个工具在任务 101 检出同一风险，归并后出现次数为 1；任务 102 再次检出后为 2。示例仅使用固定输入演示规则，不发送请求。

以上是纯转换离线验收，不涵盖真实工具执行、数据库事务或 T22 状态流转。

`to_orm_values` 将 `type` 映射到 `finding_type`、`raw` 映射到 `raw_data`，只返回现有 ORM 字段。当前 `UNIQUE(task_id, dedup_key)` 约束仅防止同任务重复插入。跨任务共用风险记录仍需服务层按资产及风险键查历史并处理并发事务，纯函数不能保障数据库中的竞态更新。此次交付不新增接口、数据库约束或迁移。
