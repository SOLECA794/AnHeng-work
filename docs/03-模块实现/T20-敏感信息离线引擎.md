## 2. 四类规则

规则配置文件位于 `src/tools/rules/sensitive-defaults.json`，通过 `load_rules(path)` 加载。规则结构对应 SDD-02 中的 `sensitive_rule` 字段。

| 类型 | 匹配对象与方式 | 使用说明 |
| --- | --- | --- |
| `KEYWORD` | 在输入正文及响应头中匹配字面关键词 | 适合合成令牌标记、单位敏感关键词；不把关键词解释为正则 |
| `REGEX` | 用正则表达式检测正文及响应头 | 适合邮箱、手机号等格式；执行有超时限制 |
| `FILETYPE` | 按资源 URL 的文件名或扩展名匹配 | 适合 `.env`、`.bak` 等暴露资源；依赖资源 URL，不能用离线物理文件名替代 |
| `SAMPLE` | 匹配字面样本，或 `sha256:<64位十六进制摘要>` | 字面样本表示内容匹配；SHA-256 对整个输入源文本计算指纹，不是任意子串的指纹 |

每条规则支持 `enabled` 与 `scope_bind`。`enabled=False` 时不参与检测；`scope_bind=None` 或空字符串时对所有已授权输入生效，设置后只在对应 `scope_id` 的授权范围内生效。绑定规则不会扩大授权范围。

默认规则服务于当前合成样例及常见格式验证，不代表覆盖所有单位的敏感数据。实际使用时应依据本单位定义维护规则，并持续补充正常样例以控制误报。

## 3. 调用接口

核心接口定义：

```python
SensitiveRule(
    id, name, rule_type, pattern,
    severity="MEDIUM", enabled=True, scope_bind=None,
)
ScanDocument(url, text="", headers={})
AuthorizedScope(scope_id, origin, path_prefix="/")
SensitiveScanner(
    rules,
    regex_timeout=0.05,
    max_content_chars=1_000_000,
    max_findings=1000,
).scan(document, scopes)  # list[dict]
load_rules(path)
```

最小离线调用示例：

```python
from src.tools.sensitive import (
    AuthorizedScope, ScanDocument, SensitiveScanner, load_rules,
)

rules = load_rules("src/tools/rules/sensitive-defaults.json")
scanner = SensitiveScanner(rules)
document = ScanDocument(
    url="http://127.0.0.1:18084/.env",
    text=provided_resource_text,  # 上游已提供的正文
    headers={},
)
scopes = [AuthorizedScope("fixture-d", "http://127.0.0.1:18084", "/")]
findings = scanner.scan(document, scopes)
```

`SensitiveToolAdapter(scanner, scopes)` 使用 T11 的 `ToolManifest` 和 `ToolResult`。目标参数是资源 URL；`params` 中提供 `text` 和 `headers`。适配器执行同一离线引擎，可交给工具注册表调用，但不负责采集目标网页。注册表的审计与调用策略沿用 T11 契约。

直接调用时，未授权目标抛出 `UnauthorizedTargetError`（`code=40310`），规则配置校验失败抛出 `RuleValidationError`，正则超时或资源超限抛出 `ScanLimitError`。文档输入类型或扫描限额参数无效时抛出 `ValueError`。适配器将未授权目标或不符合离线调用契约的参数映射为 `ToolResult.status="REJECTED"`，其他执行失败映射为 `FAILED`；失败结果不能视为“扫描完成但无风险”。

## 4. 授权与执行边界

检测前检查 `AuthorizedScope`。授权按 origin（协议、主机、有效端口）与规范化路径前缀共同判断；同主机不同协议或端口不能混用授权。路径判断以目录边界为准，例如 `/allowed` 不能授权 `/allowed-other`。路径最多进行四轮百分号解码，仍有嵌套编码歧义时拒绝；再规范化 `.`/`..` 路径段，并拒绝反斜杠及控制字符。检测使用同一规范化路径判断资源类型，减少授权判断与文件判断不一致的问题。

没有匹配的授权范围时拒绝执行，使用项目错误码 `40310`。`scope_bind` 只筛选规则，不替代授权校验。目标 URL、输入结构和规则配置错误应作为失败处理，不能当作“未发现风险”。

为防止异常输入占用资源，引擎对正则设置执行超时，并限制输入字符数与 Finding 数量。达到超时或超出上限时明确失败，不把截断结果包装为完整扫描成功。默认参数可由调用方调整。

## 5. 证据脱敏与 T21 接口

命中输出包含规则标识、规则类型、命中来源与位置，并提供脱敏证据、影响说明、修复建议及工具来源。证据固定表示为 `[REDACTED] (length=N)`，保留命中长度，不保留正文、响应头原文、完整规则表达式或邻近上下文。输出 URL 去除 query 和 fragment，并使用当前启用且适用于授权范围的内容规则及实际命中值，对规范化 URL 路径和响应头名称中的敏感内容脱敏；重叠命中区间合并处理。实际命中值仅在扫描期间使用，不写入结果或日志，因此依赖上下文的正则与 SHA-256 样例命中也能正确脱敏元数据。元数据脱敏同样受正则超时与匹配数量上限约束。

工具注册表审计对成功、失败或拒绝调用的目标使用 `sha256:<digest>` 标识，便于关联调用轨迹，避免把原始目标 URL 中的凭据或查询内容写入审计。此处哈希只用于关联；数据采集、完整审计持久化与访问权限仍由上游及后续集成承担。

T20 实际输出字段为：

```text
finding_type, severity, title, url, scope_id,
rule_id, rule_type, location, evidence,
impact, suggestion, tool_name, status, raw_data
```

其中 `finding_type="SENSITIVE"`；`raw_data` 只包含 `rule_id`、`rule_type`、`location`、`sample="[REDACTED]"`、`match_length` 和 `target_sha256`。`target_sha256` 对完整输入 URL 计算 SHA-256，供后续关联使用，无需保留原始 URL 的查询内容。T21 后续将这些字段映射到 SDD-01 的统一 Finding 结构，例如 `finding_type → type`、`raw_data → raw`。T20 不维护 Finding 数据库记录、跨轮次 `dedup_key`、`first_seen`/`last_seen` 或出现次数。

规则默认严重级别是 T20 的初始分级。根据影响面重新定级属于 T23，不能把初始级别视为完整分级模型。

`synthetic-env.txt` 和 `synthetic-backup.txt` 是仓库物理文件名，构造检测输入时必须分别使用标签中的 `/.env` 与 `/backup.bak` 作为 URL 路径，否则无法验证文件类型规则。

执行命令：

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p test_sensitive.py -v
python scripts/verify_t20.py --output reports/t20-sensitive-offline-results.json
```
