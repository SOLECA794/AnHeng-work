# T26 报告生成与导出

2026-10-19，D。基于 main `42bc12f`，独立实现 SRS-02 F5.5；不依赖待评审的 T23/T24/T25。设计扩展见 SDD-11（随 PR 评审）。

## 能力与使用

按资产和日期区间读取数据库中的任务/Finding，冻结一次报告快照，生成两种真实文件。报告包括资产/页面数、任务清单、去重风险、严重度和当前状态分布、每日趋势、证据指纹、影响及修复建议。报告以受控 Finding/任务 ID 保留追溯关系，输出不含敏感证据原文。

```python
from src.api.reporting import create_report_router
from src.repositories.reporting import SqlAlchemyReportRepository
from src.services.reporting import ReportService
from src.services.report_files import ReportStorage

service = ReportService(SqlAlchemyReportRepository(sessions), ReportStorage(".local/reports"))
app.include_router(create_report_router(service, principal_dependency=trusted_principal))
```

`sessions` 来自受控 SQLAlchemy 会话工厂；`trusted_principal` 必须由真实身份和服务器侧资产授权映射生成。B 的 JWT 已合入，但资产授权映射仍待约定，不能把请求里的 scopeIds 或全部资产授给任意登录者。工厂默认拒绝，默认应用暂未装配。

请求 `POST /api/reports/generate`：`{"scopeId":1,"periodBegin":"2026-10-18","periodEnd":"2026-10-19"}`。本版为有界同步实现，成功返回 DONE 和 HTML/PDF 下载地址；列表、详情、下载均在 `/api/reports` 下，见 SDD-11。SEC_OPS 与 RULE_ADMIN 可使用，ADMIN 不自动取得业务权限。

统计日期按上海自然日。任务时间默认使用 C 仓储的 UTC 存储约定，SQL 边界转换为 UTC、显示转换回上海；经上游确认可显式改为 `task_timestamp_zone="Asia/Shanghai"`。Finding 观测时间遵循 T21 的上海墙钟。风险状态为生成时现状，不是历史日期的处置状态。每天的风险去重数不能相加当成整个区间去重总数。

## 事务和文件边界

读取快照及 GENERATING/开始审计同事务；事务外渲染文件；DONE/成功审计另一个事务，完成前复核资产启用与授权。生成失败为 FAILED，不提供文件。PostgreSQL 使用 REPEATABLE READ，SQLite 显式读事务；生产隔离尚未实测。

私有文件目录不挂静态服务。随机目录令牌绑定 manifest 摘要，下载校验目标文件的长度/摘要，拒绝错误格式、路径穿越、链接、缺失和损坏。日志沿用 OPERATION，仅记录受控 ID 和格式。HTML 下载禁止脚本/外部资源，所有内容经过转义；PDF 由 ReportLab 生成，使用中文 CID 字体，无在线字体请求。

Windows 新文件偶发被扫描器短暂占用，目录原子发布仅对 WinError 5/32 做最多 6 次有界重试；持续错误仍正常失败。数据库与文件系统不构成一个原子事务。崩溃可能保留 GENERATING 或未引用目录；未 DONE 文件不下载，不盲删可能已提交的 bundle。部署方需提供私有目录 ACL、磁盘监控、孤儿核对和恢复策略。20MB 单文件上限、366 天/1000 任务/1000 Finding 上限均显式拒绝，不静默截断。

## 验证与复现

```powershell
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests/unit -p test_reporting.py -v
python -m unittest discover -s tests/integration -p "test_reporting*.py" -v
python scripts/verify_t26.py
python -m unittest discover -s tests/unit -t tests/unit -q
python -m unittest discover -s tests/integration -q
```

专项 43 项（7 契约单元 + 28 数据/事务/文件 + 8 API）；验收脚本 14 场景。`reports/t26-acceptance.json` 可重复生成，包含逐项结果和可核对统计。脚本使用私有 SQLite 和固定合成数据，实际经过 ASGI 生成和下载，不读取 `.env` 业务数据库、不扫描外部站点。示例固定时钟 23:59:59 仅为验收数据，不是实际操作时间。

最终回归：全量单元 350 项通过；全量集成实际执行 66 项通过，另有两个 PostgreSQL 测试类因本机数据库不可达跳过，未运行其真库断言。上述跳过不计为生产持久化验证通过。

生成 `output/pdf/report-t26-20261019.pdf` 与同名 HTML；两页 PDF 已逐页渲染检查中文、分页与证据/建议。生成物被忽略，仓库保留代码和 JSON 验收记录。当前环境 Poppler 因中文用户路径无法读取语言包，使用 MuPDF 成功渲染复核；PDF 中文提取由 pypdf 自动验证。

部署 PostgreSQL、真实用户到资产授权、前端按钮、在线采集到报告全链路仍需 B/E/F 联调。当前独立验收不等同 T41 公网用例已通过。
