# T23 · 风险分级模型

> 日期：2026-10-15；责任人：D；依据：SRS-02 F4.4、SDD-01 §5.6、SDD-08。

## 1. 本次交付

`src/services/risk_grading.py` 实现可配置的独立分级服务。漏洞采用已有 CVSS v3.1 分数映射；挂马、外链、篡改、敏感信息等按工具及命中规则定级，未配置的规则保留检测器级别。页面重要性与暴露范围设置最低处置级别，取最高值而不叠加升级，INFO 保持 INFO。每条结果带基础级别、最终级别、调级理由、策略版本及策略摘要。

CVSS 对应关系见 [FIRST CVSS v3.1 表 14](https://www.first.org/cvss/v3.1/specification-document#i5)。本服务只转换已有分数；不会计算向量或把影响面调整宣称为新的 CVSS 分数。默认将重要页面和互联网暴露的非 INFO 风险最低定为 HIGH，是本项目可配置的处置策略，随 PR 评审。

证据保留 T21 的脱敏指纹；影响说明及可执行修复建议使用固定分类模板。原始 URL、工具自由文本、命中内容与规则 ID 均不会写入分级解释。原始规则 ID 仅以 SHA256 标识；输出的页面重要性与暴露范围为枚举。

## 2. 策略与调用方式

策略文件为 `src/config/risk-grading.json`。`page_floors`、`exposure_floors` 分别定义影响面的最低级别；`rule_overrides` 按 `(type, tool_name, rule_id)` 精确匹配。支持配置快照校验及规范 JSON 的 SHA256，修改策略会改变摘要。禁止重复 JSON 键和重复规则，限制文件大小为 64 KiB、规则数为 256。

```python
from src.services.findings import deduplicate_findings
from src.services.risk_grading import (
    GradingContext, load_grading_policy, grade_finding, graded_orm_values,
)

# normalized_findings 是 T21 已脱敏标准记录；先去重再分级。
record = deduplicate_findings(normalized_findings)[0]
context = GradingContext(
    scope_id=record["scope_id"],
    target_sha256=record["raw"]["identity"]["target_sha256"],
    page_importance="CORE",  # 来自可信的页面/资产元数据
    exposure="INTERNET",    # 来自可信的授权资产配置
    rule_id="known-rule",   # 非漏洞类型，可选；须由适配层提取
)
policy = load_grading_policy()
result = grade_finding(record, context, policy)
orm_values = graded_orm_values(record, context, policy)
```

漏洞传入 `cvss_score`，不使用 `rule_id` 覆盖。缺失 CVSS 回退到检测器等级并明确标记；非法分数拒绝处理，不当作零。未知页面/暴露范围明确为 UNKNOWN，不从已脱敏显示 URL 猜测。上下文必须绑定相同 scope_id 和目标指纹；资产事实的真实性仍由上游可信服务保证，本函数不是鉴权接口。

例如同一条基础 MEDIUM 的敏感信息风险，在普通内网页面上保留 MEDIUM；互联网暴露时依默认策略为 HIGH，并保留基础等级和调级原因。T19 黑名单脚本规则按精确工具名及规则配置为 HIGH。T18 篡改结果可直接经 T21 归一化后使用，不需要改动 C 的检测器。

## 3. 与 T21/T22 及数据库的边界

- T21 标准记录保持不变；分级结果是独立展示结构，`graded_orm_values` 返回 ORM 字段映射并添加 `raw_data.grading`，不写数据库。
- 归一化身份、去重键、证据、状态及 first_seen/last_seen 不变。已确认或误报状态不会因重新分级而重置；T24 告警仍需检查状态，T23 不触发告警。
- T21 对历史记录的文本及 raw 白名单保持严格。T23 的 ORM 值不能直接作为 T21 历史输入；调用方保留标准快照，历史归并后重新分级。生产持久化的历史读取适配另行联调。
- 两项数据库往返测试只使用 T22 的隔离 SQLite 夹具，验证 ORM 字段可存取；未执行 PostgreSQL 实库或迁移，没有挂载新 API。
- 恒脑生成增强说明、在线采集、流水线调度属于后续集成；本次规则兜底独立可运行，不依赖智能体 ID。
