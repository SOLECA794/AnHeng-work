## 2. 今天实际新增了什么

过去 D 路由需要测试或调用方直接构造可信 Principal，尚无 B 的登录结果到 D 权限上下文的适配。今天增加：

- `src/auth/d_principal.py`：复用 B 的 `current_user`，真实 JWT 必须通过签名/有效期、退出吊销、当前账号启用状态、密码和角色变更检查；服务器授权解析器再返回资产 ID。
- `src/api/d_module.py`：将验证、告警、复测、报告四组既有接口统一装配，使用同一个身份桥。没有解析器时为空授权，不会自动开放所有资产。
- `src/api/finding_verification.py`：D 的安全路由处理依赖层 401 时补充 `WWW-Authenticate: Bearer`，保持统一错误信封。
- SDD-12、9 项身份桥单元测试、23 项真实 JWT/私有 SQLite 集成测试及可复现验收脚本。

32 项专项全部通过，覆盖四组路由、确认写入及真实处理人审计、退出/改密/停用/删除/角色变化、跨资产、动态撤权、伪造头和 Token、异常/非法授权返回脱敏。全量单元 **409 项**、集成实际执行 **161 项**通过；另两个 PostgreSQL 测试类仍因本机缺少所需驱动跳过，不计作真库验收通过。

本轮真实 JWT 是由私有数据库内的真实认证服务签发，不是伪造请求头或直接注入 Principal。不过，服务器授权解析器在测试中使用受控内存映射，**生产用户—资产 ACL 存储和维护服务并未因此建成**。

## 3. 如何交给 B 装配

宿主应用在创建受控服务实例后，可显式挂载：

```python
from src.api.d_module import DModuleServices, create_d_module_router

# verification_service 等对象使用同一受控环境的会话工厂；用户 ID 命名空间应与认证存储一致。
services = DModuleServices(
    verification=verification_service,
    alerts=alert_service,
    retesting=retest_service,
    reports=report_service,
)
app.include_router(create_d_module_router(
    services,
    grant_resolver=server_grants.resolve_scope_ids,
))
```

上例中服务对象和 `server_grants` 均由宿主提供，不能直接复制为一段自动创建生产权限的代码。解析器契约是同步 `resolve_scope_ids(user_id) -> frozenset[int]`；不得从请求体、X-Role、X-Scope-Ids 或未经校验的自定义 Token claims 生成权限。缺失解析器相当于无资产权限，解析异常/非法集合返回安全的 50000。

默认 `src.main` 仍只挂载健康、认证和管理员平台审计。B 在正式数据源与生命周期管理就绪后主动装配；本次没有自动修改默认入口。授权在每请求重新读取，撤权对下一请求生效；不承诺取消已经在执行的长请求，生产长任务仍需额外的授权版本或完成前复核机制。
