# 04 · C 组对 SDD-04 工具注册表契约的核对反馈

- 日期：2026-10-12
- 提出方：C 组
- 对象：B 组（① 需 F 组一并确认）
- 依据：`specs/02-设计规格/SDD-04-工具注册表契约.md`、`src/tools/contract.py`（提交 `23eaac7`）

## 0. 结论

SDD-04 与 `src/tools/contract.py` 已收到，C 组确认可按契约接入，T15–T17 的阻塞解除。

核对中发现 **3 处跨文档不一致**：① 阻塞适配器 `manifest.categories` 的填写（须先定口径），②③ 属 B 侧实现与其自身契约/规格的缺口。均为对接口径问题，不影响 C 组先行开发。

## 1. ① category 词表三处不一致（阻塞 T15–T17）

| 来源 | category 词表 |
| --- | --- |
| SDD-04 契约 §1 | `VULN`、`WEAK_CONFIG`、**`FINGERPRINT`**、`TAMPER`、**`EXTERNAL_LINK`**、`SENSITIVE` |
| SDD-02 数据模型 §4.6 `finding_type` | `VULN`、`WEAK_CONFIG`、**`MALICIOUS_LINK`**、**`MALICIOUS_SCRIPT`**、`TAMPER`、`SENSITIVE` |
| T40 样例集 v1.0.0 `category` | `VULN`、`WEAK_CONFIG`、**`MALICIOUS_LINK`**、**`MALICIOUS_SCRIPT`**、`TAMPER`、`SENSITIVE` |

三处差异：

1. **同义不同名**：契约的 `EXTERNAL_LINK` ≡ 另两份的 `MALICIOUS_LINK`；
2. **契约缺失**：契约没有 `MALICIOUS_SCRIPT`，而 T40 样例集已按此标注（B-03/B-04，挂马脚本正负例）；
3. **契约多出**：`FINGERPRINT` 不在另两份中——它描述的是 Wappalyzer 的**工具能力**（技术栈识别），本身不产出风险 Finding。

**影响（不修会怎样）**：C 的 T19 适配器 `manifest.categories` 无论填哪个词都会错位——填 `EXTERNAL_LINK`，智能体按 SDD-02 的 `MALICIOUS_LINK` 检索工具时找不到；结果归一化与 T42 的检测效果统计（按 category 汇总）同样会对不上。

**C 组建议**：以 **SDD-02 + v1.0.0 样例集**为准（二者一致，且是 `finding_type` 的正式定义；样例集已发布，改动成本高）。将 SDD-04 §1 的 `categories` 调整为：

```
VULN、WEAK_CONFIG、FINGERPRINT、MALICIOUS_LINK、MALICIOUS_SCRIPT、TAMPER、SENSITIVE
```

即 `EXTERNAL_LINK` 拆为 `MALICIOUS_LINK` + `MALICIOUS_SCRIPT`（口径：页面**指向外部**的链接归 `MALICIOUS_LINK`；被注入/执行的**脚本、iframe、跳转**归 `MALICIOUS_SCRIPT`），并保留 `FINGERPRINT`。

同时在 SDD-04 §1 明确二者关系：**`categories` 是工具能力标签，是 `finding_type` 的超集**（多 `FINGERPRINT` 一项），避免后续再混。

> 待确认期间，C 组按 SDD-02 口径先行实现，代码内以注释标注待定项；口径落定后为一行改动。

## 2. ② 注册表未实现限速与超时

SDD-04 §3 规定执行前按顺序校验：「已注册 → 已启用 → `read_only=true` → `non_destructive_check` → **限速/超时**」；清单 T11 验收要点亦写明「**限速生效**」。

但 `ToolRegistry.execute()`（`src/tools/contract.py:70-80`）实际只做到 `non_destructive_check`，随后直接 `adapter.run()`——**限速与超时均未实现**。

**影响**：验收标准 §4「限速：请求频率受限，目标负载受控」与 SRS-02 F2.1 的限速要求无法落地；`manifest.rate_limit` 与 `timeout_seconds` 两个字段目前是「登记了但不生效」。

**建议**：由 B 在注册表层实现（契约 §3 明确注册表是唯一事实源，限速不宜由适配器各自兜底）：按 `rate_limit.requests_per_minute` / `burst` 做令牌桶或最小间隔控制，`timeout_seconds` 作为 `run()` 的执行上限，超时返回 `status=TIMEOUT`。

## 3. ③ `ErrorCode` 缺少 40901 / 40902 / 40903

SDD-03 §3 定义了三个序号类错误码，`src/core/errors.py` 中缺失：

| 错误码 | SDD-03 含义 | C 组用途 |
| --- | --- | --- |
| 40901 | 重复操作（域名已存在 / 任务已存在） | T12 授权资产录入时域名重复 |
| 40902 | 状态不允许（任务/计划状态不满足） | T13 计划启停 / 任务重试的状态校验 |
| 40903 | 无可执行内容（无页面/无规则/无数据） | T13/T14 巡检无可发现内容 |

**影响**：直接阻塞 C 组 T12/T13 的错误返回口径。

**建议**：B 在 `ErrorCode` 中补齐三项。C 组在补齐前，服务层先以 SDD-03 的字面值常量实现，待枚举就绪后替换。

## 4. 附：导入风格不一致（不阻塞）

B 组使用绝对导入 `from src.core.config import ...`（需仓库根目录在 `sys.path`）；C 组既有代码使用 `from services.discovery import ...`（需 `src/` 在 `sys.path`）。

两种风格并存会在合入与联调时产生摩擦。**建议统一为 `src.xxx` 绝对导入**（与 `uvicorn src.main:app` 的启动方式一致），C 组在合入时统一调整。
