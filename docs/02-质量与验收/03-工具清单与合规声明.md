# 03 · 工具清单与合规声明

> 状态：基线 v1.0（规划清单；工具实际接入后补充版本与实测项）
> 关联设计：SDD-01 §5.3（工具层）、§5.8（非破坏与合规）

## 1. 工具白名单机制说明

**工具白名单**是指：系统只允许执行"已登记且通过非破坏校验"的工具，未登记、已停用或具有破坏性的工具一律拒绝。这是本项目安全合规（非破坏性、最小权限、可审计）的核心控制点。

实现机制：

| 控制点 | 落地 |
| --- | --- |
| 工具注册表 | 每个工具唯一登记：名称、能力声明、检测类型、执行模式、限速参数、非破坏声明、启停状态 |
| 执行前校验 | 每次调用强制校验：注册表存在 + enabled + `non_destructive_check()` 通过，任一失败即拒绝并留痕 |
| 智能体工具选择 | 智能体只能从注册表可见工具中选择；工具描述来自注册表，防止幻觉调用未授权工具 |
| 审计 | 每次工具调用写 agent_log（工具、参数摘要、状态、耗时） |
| 准入流程 | 新增工具走评审：能力说明 → 非破坏评估 → 登记 → 实测 → 定版 |

### 2.3 明确禁止项（破坏性/违规动作）

- 漏洞利用与验证性利用（exploit、payload 投递）；
- SQL 注入、XSS 注入、命令注入等攻击性输入；
- 暴力破解、撞库、DoS/压力测试；
- 绕过 WAF/认证的检测；
- 对未授权目标发起任何请求；
- 修改目标内容的任何动作。

## 3. 工具准入流程（新增工具）

1. 提交能力说明（检测类型、原理、误报风险、资源消耗）；
2. 非破坏评估（是否只读/是否改变目标状态/是否触发告警风险）；
3. 适配器实现（实现 `ToolAdapter` 接口 + `non_destructive_check`）；
4. 登记注册表（名称、能力、限速、启停）+ 评审通过；
5. 实测与定版（在测试集上验证，更新本文档工具清单）。

## 4. 合规声明

本项目所有检测活动仅在**授权资产范围内**、以**非破坏方式**进行：

- 授权边界：未授权目标一律拒绝（40310）并留痕；
- 限速：全局与按站点 QPS 限制，避免影响目标站点；
- 最小权限：工具容器非 root，服务账号最小权限，敏感数据脱敏；
- 审计：巡检、工具调用、结果操作全量留痕；
- 数据：用户数据与检测数据自持，不随平台流转（仅必要的智能体调用参数外发）。
